# v0.1-029 光照贴图交付说明（给程序）

美术，2026-10-30。每个场景一节（S1 / S2 / S3），完成一节补一节。
烘焙过程、参数和重建命令见 `art/source/bake/README-029.md`。

## 0. 三个场景通用

### 编码（按「编码定案」）

| 项 | 值 |
|---|---|
| 格式 | KTX2 UASTC LDR（`toktx --uastc 3 --uastc_rdo_l 1.0 --zcmp 19`），带完整 mip，2048² |
| 色彩空间 | 线性：`--linear --assign_oetf linear`，没有标 sRGB。three 里设 `colorSpace = THREE.NoColorSpace` |
| 编码 | RGBM，范围 8：`E = rgb · a · 8`（rgb、a 都是 0–1） |
| 截断 / 下限 | 大于 8 的截断（实际最大约 0.7，没有被截断的像素）；暗部 alpha 下限 1/255 |
| 单位 | `E` = three 的辐照度（与 `HemisphereLight` 算出来的 irradiance 同单位），只含天光 + 太阳反弹，**不含太阳直射**（太阳仍是实时光 + 阴影） |
| `lightMapIntensity` | **1.0**（S1/S2/S3 外景；S2 室内另见 S2 节） |

### three 接法

- `tex.channel = 1`（UV2）、`tex.flipY = false`。
- 挂了光照贴图的材质**去掉半球光**（光照贴图里已经有天光）。礁石、道具等没挂的仍用半球光。
- 着色器替换（`art/tools/preview/lightmap029.html` 的 `rgbmLightMap()` 可以直接抄）：

```js
// lights_fragment_maps：
vec3 lightMapIrradiance = lightMapTexel.rgb * lightMapTexel.a * 8.0 * lightMapIntensity;
// lights_fragment_begin：去掉 getHemisphereLightIrradiance(...) 那一行
```

- ORM 里的 AO 贴图可以保留；觉得叠得太暗就把 `aoMapIntensity` 调到约 0.5。

### UV2 与 GLB 约定

- **UV2：** glTF `TEXCOORD_1` = three 的 `uv1`（`texture.channel = 1`）。已经换成场景图集坐标，LOD0/1/2 共用 LOD0 的分块。
- **根节点 extras：** 节点名不变，根节点上加了 `extras.lightmap`：

```json
{ "ticket": "v0.1-029", "texture": "tex-…-lightmap.ktx2", "encoding": "RGBM8", "uv": "TEXCOORD_1", "lightMapIntensity": 1, "rect": [u0, v0, w, h] }
```

- 程序按根节点的 `texture` 挂贴图即可。`rect` 只是告诉你这个物体占图集的哪一块（已经烤进 UV2，不用再变换）。各 `_lod*` 节点上也有一份 `extras.lightmap`（size / charts / texelsPerM）。
- **只挂可见网格：** `-collider`、`-wall` 节点不挂光照贴图。
- **不进光照贴图的东西：**
  - 会动的门：只参与挡光，烘焙时按打开 −100° 放；
  - 礁石实例、道具、小船、浮台。
  - 它们照旧用半球光，或用探针（见下）。
- **光照探针：** 没有导出。建议程序在引擎里用 `LightProbeGenerator` 自己烘，给不挂光照贴图的动态物体用。

### 对比解码用的同机位图

- **页面：** `art/tools/preview/lightmap029.html`（S1）和 `lightmap029-s23.html`（S2 / S3）。
- **用法：** `?mode=irr` 时是白色 `MeshBasicMaterial` + 光照贴图 × π。这样屏幕上的值就是线性 E，没有色调映射、雾和实时光。程序用同样的设置渲一张，就能和 `art/source/bake/preview/029-*-irr.png` 逐像素对比。
- **原始数据：** 未编码的 EXR 在 `art/source/bake/<场景>/tex-*-lightmap.exr`。half float、ZIP 压缩、Non-Color，第一行 = glTF v=0，值就是 E。可以拿来和解码结果对比。

### fix-r2（10-30 20:00）：崖顶 material 2 UV2 越界

- **问题：** `env-clifftop-s2.glb` 的礁石（material 2）UV2 有一部分在 [0,1] 外（u −0.032 – 1.019；越界顶点 LOD0/1/2 = 1,680 / 914 / 202），原因是俯视投影框只按 LOD0 地面算，没包住石块。
- **改法：** `art/tools/build-env-s2.mjs` 的 `finishAsset` 加了 `uv2PlanarFitAll`（崖顶开启）：投影框改为包住全部 LOD 顶点的 xz 正方形，仍是 4 px 边距的俯视投影，然后照常走 `lightmap-uv2.mjs` 分块（4,099 块，LOD1/2 全部三角形落在块内，0 个顶点在块外）。除 `TEXCOORD_1` 外，位置、法线、UV0、索引、碰撞体、墙都和原来逐字节一致。LOD1/2 顶点因为按块切缝多了 27 / 26 个（42,637 → 42,664，28,963 → 28,989），三角形数不变。
- **结果：** 各 LOD UV2 都在 [0.0020, 0.9980]，**越界顶点 LOD0/1/2 = 0 / 0 / 0**，进 4 px 边距的也是 0。礁石那段 `TEXCOORD_1` 从 float 变成和地面一样的 uint16 归一化（three 自动处理），GLB 3,499,980 → 3,361,480 B。密度 45.8 → 43.4 texel/m。
- **光照图：** 整图重烘（dir+ind 256/512，S2 雨后阴天 0.18 / 0.7，方案 C 不变；`lm_post --tide -1000`，无补光，同原来），编码不变（RGBM 8，UASTC LDR 线性，`--uastc 3`，RDO 1.0，zstd 19，12 级 mip，2048²），`tex-s2-clifftop-lightmap.ktx2` 1,501,584 → 1,359,623 B。mip0 相对误差 p50 / p90 0.2% / 2.5%。
