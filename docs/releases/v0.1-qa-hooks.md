# v0.1 QA 钩子与 M7 冒烟用法（程序，2026-11-01）

## 控制台钩子 `__qa`（M7 新增，commit 573f551）
**batch25 起**：只在 `npm run dev`（开发服务器）和**测试构建**（`vite build --mode smoke`）里有（`__game`、`__perfSpot`、`__s1`/`__s2`/`__s3`、`__testbed` 同样）。生产构建（`npm run build` → dist/）里这段代码在构建期被摇树删掉，线上加 `?smoke=1` 也拿不到；`npm run verify:prod-hooks`（check:release 的一步）断言 dist 里没有这些字符串。
打开方式：`npm run preview:smoke`（临时建测试构建到 /tmp，在 4173 起 vite preview，Ctrl+C 退出时删掉）后访问 `http://localhost:4173/?smoke=1`，F12 控制台；或 `npm run dev` 后访问 5173。

所有依赖这些钩子的脚本（smoke、smoke:xb、verify-budget / load / memory、shots-*、check-027、probe-d2）都经 `scripts/lib/test-server.mjs` 起服务：
- 默认：临时建一份测试构建到 `/tmp/foglight-smoke-dist-XXXX`（约 220 MB，含美术拷贝；本机约 2 s），跑完删除（Ctrl+C / timeout 的 SIGTERM 也删）；不碰 dist/。
- `SMOKE_DIST=<目录>`：复用已建好的测试构建（不是测试构建会直接报错）。`node scripts/with-smoke-build.mjs "<命令>"` 建一份、设好 SMOKE_DIST 跑命令、跑完删——check:release 用它让 verify:budget / load / memory 共用一份。
- `SMOKE_DEV=1`（smoke）/ `XB_DEV=1`（smoke:xb）：vite 开发服务器。

| 调用 | 返回 |
|---|---|
| `__qa.puzzles()` | 当前场景所有谜题的状态快照（不在 S1/S2/S3 时为 null）。只含确定性字段，可以直接 JSON 比较。S1：tide{state,level}、bellRings、raft、raftMoved、p1Solved、p2Solved、reefGate；S2：journalRead、lanternOnDesk、lockOpen、doorOpen、hasKey、keyInHand、digitsSeen、gateOpen、westBlockedSaid、holding、mirrorA/B 角度、lock 状态、dials（拨盘当前数字）；S3：tide、bellRings、doorOpen、valveOpen、reached、igniting、ignited、igniter、mirrors{window,a,b} 角度 |
| `__qa.save()` | localStorage `foglight.save.v1` 的内容（解析后的对象；坏档返回 `'unparsable'`，无档 null） |
| `__qa.saveData()` | 存档系统内存里最近一次写入的存档（刚读档、还没写过时为 null） |
| `__qa.scene()` | 场景名、输入上下文、当前目标、readDocs、玩家位置 |
| `__qa.diff(a, b)` | 两份快照的差异列表，一样时返回 `[]` |

手工验存档的例子：进 S2 后先 `a = __qa.puzzles()`（这一刻就是进场自动存档时的状态）→ 解一半谜题 → 刷新 → 继续 → `__qa.diff(a, __qa.puzzles())` 应为 `[]`。
**设计说明**：v0.1 只在进场景时（和章节结束时）自动存档，读档总是回到场景入口、谜题全部回到初始（GDD §11）。所以「读档后和存档前一致」指的是和**进场存档那一刻**一致，场景里做到一半的进度不保留。

## M7 新冒烟项（scripts/smoke-browser.mjs）
跑法（在 game/ 下；脚本自己建临时测试构建，不需要先 build）：

| 项 | 命令 | 无头软件渲染大约耗时 |
|---|---|---|
| 完整通关 + 存档读档 | `SMOKE_ONLY='v0.1-M7 完整通关' timeout 1800 npm run smoke` | 见 compat-report 实测 |
| 切画质 | `SMOKE_ONLY='v0.1-M7 切画质' timeout 1800 npm run smoke` | 同上 |
| 两项一起 | `SMOKE_ONLY='v0.1-M7' timeout 2400 npm run smoke` | |

- 完整通关：主菜单「新游戏」→ S1 中途（退潮 + 谜题 1 + 读纸条）刷新 →「继续」→ 断言谜题和存档与进场存档时一致 → 解完 S1 走出口 → S2 中途（日志 + 灯台 + 镜子开锁 + 地窖门）刷新 → 继续 → 断言一致 → 解完 S2（钥匙、观察点 317、拨盘）走出口 → S3 中途（退潮 + 开门 + 开阀）刷新 → 继续 → 断言一致 → 解完点灯 → 按住 Space 跳过结尾 → 结束页（存档 chapterComplete）→ 刷新 →「继续」回结束页 → 回主菜单 →「新游戏」覆盖确认 → 清档进 S1。
- 切画质：S1/S2/S3（art=1）各切 ultra → high → standard → high → ultra（batch25 加了 standard → high），每次断言没有 GL 错误 / 上下文丢失、截图不是黑屏或纯色、可交互物 / 出口 / 汐都还在场景里且可见。
- 解谜用的是单项冒烟同样的捷径（传送、机关按键注入、beam.solve），不验操作手感。
- GL 错误断言（batch25）：除走出口进场外，刷新后「继续」进 S1 / S2 / S3 / 结束页、主菜单新游戏进 S1（首次 + 覆盖确认）、S3 按 E 点灯 → 结尾演出 → 跳过 → 结束页全程，都断言 `gl.getError()` 为空。

### M7 完整通关用到的捷径，以及别的冒烟项是否用真实输入覆盖（batch25）
输入分四层（从真到假）：**真实输入** = CDP `Input.dispatchKeyEvent / dispatchMouseEvent`（浏览器可信事件，经 DOM 监听 → 输入系统）；**合成 DOM 事件** = 页面里 `window.dispatchEvent(new KeyboardEvent)`（走游戏的 keydown 监听，但 isTrusted=false）；**setRaw** = `__game.input.setRaw('smoke', code)`（跳过 DOM 监听，之后的按键映射 / 上下文 / 交互选择照常）；**直接调用** = `interaction.trigger` / `events.emit('interact:used')` / `beam.solve()` / 直接改位置（跳过输入和交互选择，有的连动作 / 谜题过程都跳过）。

| # | M7 里的捷径 | 跳过了什么 | 别的冒烟项覆盖（层级） | 有没有真实输入覆盖 |
|---|---|---|---|---|
| 1 | 菜单「新游戏 / 继续 / 回主菜单 / 覆盖确认」 | —— | M7 本身用 `cdp.click`（真实鼠标）；008 主菜单也是 | ✓ 本身就是真实输入 |
| 2 | 角色位置 `teleport` / `position.set`（S1 tp1、S2 tp2 / 站位、S3 拉杆站位） | 走路、寻路、碰撞 | 002 角色控制器（测试场 setRaw A + Shift 走 / 跑速度）、013 S1 退潮后 setRaw W 走下台阶 | ✗ 没有真实 WASD 走路；001 键位映射用的是合成 DOM 事件 |
| 3 | 出口：瞬移到出口触发体外再进 | 走到出口 | 010 场景流程同样瞬移；smoke:xb 也是 | ✗ |
| 4 | S1 敲钟 `events.emit('interact:used', tide-bell-s1)` | E 键、交互选择、xi-ring-bell 动作 | 017（art=1）S1 / S3 美术钟 `interaction.trigger`（有动作、钟摆）；011 测试场敲钟 setRaw E（真实 6 s 退潮） | ✗ 敲钟没有真实 E |

结论：真实输入（CDP 可信事件）只覆盖菜单点击、Esc 暂停 / 指针锁定、Tab / D / A / J（阅读与日志）、R 放回浮台、E 读文档 / 进测试场机关台、O / U（测试场灯台 / 油阀）、Space 推进字幕。**玩法主路径（走路、敲钟、推浮台、转镜、拨盘、开阀、拉杆、按住跳过）都没有真实输入覆盖**，靠 setRaw / 直接调用；setRaw 之后的输入映射、上下文切换、交互选择是真代码路径，缺的是「浏览器真实按键 → DOM 监听」这一层和操作手感，这部分仍需人工过一遍（compat-report §7）。

## 兼容性冒烟（scripts/smoke-xbrowser.mjs，`npm run smoke:xb`）
playwright 不进项目依赖，装在仓库外：
```
cd game
PW_MODULE=/workspace/pw-tools/node_modules/playwright/index.mjs PLAYWRIGHT_BROWSERS_PATH=/workspace/pw-browsers \
  XB_BROWSER=firefox timeout 1500 npm run smoke:xb
# WebKit 需要额外系统库（解在 /workspace/pw-libs，未装进系统）。MiniBrowser 包装脚本会覆盖 LD_LIBRARY_PATH，
# 所以已软链进 /workspace/pw-browsers/webkit-2370/minibrowser-wpe/sys/lib，直接跑即可：
XB_BROWSER=webkit timeout 600 npm run smoke:xb
# 真美术（art=1）：这台 box 的 WPE 没有音频解码插件，decodeAudioData 永不返回，必须加 XB_AUDIO_DECODE=reject
XB_BROWSER=webkit XB_QUERY=art=1 XB_AUDIO_DECODE=reject timeout 900 npm run smoke:xb
# 手机模拟：XB_DEVICE='iPhone 15'（webkit）或 XB_BROWSER=chromium XB_DEVICE='Pixel 7' XB_CHROMIUM_PATH=/opt/google/chrome/chrome
```
流程：主菜单 → 新游戏 → S1 首帧可操作 → 出口 → S2 → 出口 → S3 → 刷新 →「继续」回 S3；任何 console.error / 未捕获异常算失败；输出 WebGL 渲染器、KTX2 转码目标、半浮点扩展、场景贴图格式。`XB_KEEP_SHOTS=1` 保留截图（打印目录）。
