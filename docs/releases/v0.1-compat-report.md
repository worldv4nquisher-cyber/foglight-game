# v0.1 兼容性报告（M7，程序，2026-11-01）

范围（制作人 02:34）：桌面优先——Chromium（Chrome / Edge）、Firefox、Safari（WebKit 近似）；手机只要求「能打开，并给出正确提示或能运行」，画质不论。
所有结果都在 box 上无头 + 软件渲染得到（Chrome = SwiftShader，Firefox = llvmpipe，WebKit = WPE 的 GL 模拟），**只能证明「能跑、不报错、画面不黑」，不能代表真机帧率、显卡兼容和音频表现**。
dist：M7 修复后原地重建的本地自检 dist（未发布）。

> **WebKit ≠ Safari。** playwright 的 WebKit 是 Linux 上的 WPE 端口：和 Safari 是同一个 JS / CSS / WebGL 前端，但 GPU 后端、媒体栈（GStreamer vs AVFoundation）、字体、音频输出、内存限制都不同。它能抓到「Safari 引擎层面」的问题（例：BUG-034 的 console.error 只有 WebKit 报红），但结论不能代替真 Safari——见文末真机清单。

WebKit 环境限制（不是游戏问题）：
- 这台 box 的 WPE 没有 GStreamer 解码插件，`decodeAudioData` 连 WAV 都永不返回 → 带 art=1 时卡在启动、主菜单不出。为此 smoke:xb 加了 `XB_AUDIO_DECODE=reject`（把解码换成立即 EncodingError），顺带模拟 Safari 18.4 以前解不了 Ogg 的情况：**音频全缺时游戏能正常进菜单、进三个场景**。
- AudioContext 一直是 `interrupted`（无音频输出设备），点击后也不变；真机需确认声音。
- `document.fonts` 枚举为空（WPE 的 FontFaceSet 迭代），中文显示正常（截图可读）；真机需看字体。
- 渲染器名伪装成 "Apple GPU"，KTX2 转码目标是 BC（dxt / bptc）；真 Mac（Apple Silicon）会走 ASTC / BC，iPhone 走 ASTC。

## 3 ramp sRGB 调查（只查不改，制作人 02:52 ④；用户 02:36 选方案 A）
- 现状：manifest 里 tex-xi-ramp 没写 `srgb:false` → AssetLoader 设 SRGBColorSpace → 采样时做 sRGB 解码。
- 美术原意是**线性数值**：gen_tex_char_xi.py 第 328–332 行把 `smooth(0.46, 0.52, r)` 直接 ×255 写进 PNG；四张 ramp 的 KTX2 DFD transfer = 1（linear）；README-028 写的是「读 R = 受光比例」。所以 **sRGB 解码不是有意的**，是 manifest 默认值带上的。只有 tex-xi-ramp 在代码里被采样，另外三张（char / env / metal-wet）目前没用。
- 若改 NoColorSpace：lit = 0.5 的明暗分界从 90.04° 移到 91.15°（往暗面约 1.1°，u 偏 0.0097 ≈ 2.5 texel）；10%–90% 软边从 3.3° 变宽到 4.2°；单点 lit 最大差 0.29（texel 125），只影响 13 个 texel；汐头部上约 2 mm，正常机位 1 px 左右。
- **结论：不改，画面不变**（方案 A）。以后若要按美术原意，manifest 加一行 `srgb:false`，但暗部略多、软边略宽，需要美术再看一眼。

### verify:prod-hooks 已知局限（batch28 QA 记录，规则不改）
verify:prod-hooks 是**静态正则检查**：它能拦住已列出的写法（URLSearchParams / location.search / searchParams、`location[…]`、切 href、`URL.search`、`document.URL` 等），但**不能保证**拦住所有读取地址或查询串的写法。batch28 QA 确认下面 6 种间接写法检查器拦不住（rc 0）：
1. 解构：`var {search: s} = location`；
2. 先把 href 存进变量再切：`var h = location.href; h.split("?")`；
3. `String(location).split("?")`；
4. 模板字符串：`` `${location}`.split("?") ``；
5. `location.hash`（片段里也能带参数）；
6. `performance.getEntriesByType("navigation")[0].name`。

M8 候选包 fcd796a 的 dist 里这 6 种都是 0 处（QA batch28 检查结果），所以不算 bug，记为已知局限，**不为它们改规则**。「生产包不读 URL 参数」靠两点保证：源码里 URL 读取都受构建期常量 TEST_BUILD 控制，加上代码审查；检查器只是辅助，并非完整保证。

## 7 需要用户在真机上确认

### 手机 / 平板 / 触屏笔记本：BUG-035「仅支持电脑」提示（eda3534）
判定逻辑：`src/platform/desktopOnly.ts` `isDesktopOnlyBlocked`，页面加载时只算一次，按顺序：
- ① `(any-pointer: fine)` 且 `(any-hover: hover)`（有鼠标或触控板）→ **放行**。
- ② `(pointer: coarse)` 且不满足 `(hover: hover)` → **拦**。
- ③ 媒体查询**不可用或没下结论**（浏览器不支持 / 没有 matchMedia；或者能用，但没有精确指针，主指针又不是「coarse 且不能悬停」——通常是主指针不报 coarse，前两条都没命中）时：移动系统或 Mobi UA、有触摸、且没有精确指针（媒体查询可用时 `(any-pointer: fine)` 为假）→ **拦**。代码：`p.mobileOs && p.hasTouch && !(p.mediaKnown && p.anyFine)`。
- 其余 → 放行。

「拦」= 主菜单只剩标题「雾灯」，下方居中显示 `ui.notice.desktop_only` 文案「目前只支持电脑浏览器。请在电脑上用 Chrome、Edge、Firefox 或 Safari 打开。」，上方有一截细琥珀线；「新游戏 / 继续 / 设置」等按钮全部隐藏，存档提示也不显示。
「放行」= 和桌面一样显示菜单按钮、没有提示。
因为只在加载时判定一次，接上或取下鼠标、键盘之后都要**刷新页面**再看。

1. 打开游戏地址，等主菜单出来（背景是实时海面场景）。
