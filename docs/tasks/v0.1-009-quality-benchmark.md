# v0.1-009 画质三档参数表与自动检测

- **负责人**：程序
- **里程碑**：M4
- **依赖**：006
- **工时估算**：1.5–2 人日

## 背景
GDD §14（画质分档、自动画质检测（每轮 3 秒，最多 3 轮）、基准 RTX 3060 / 1440p / 极致 60fps、最低 GTX 1650）；**参数以 `art/style/style-guide.md` §8 为准**。现有 `src/config/quality.ts` 已有 ultra/high/standard 和 `lodDistances`，但：①只覆盖少量参数；②按 GPU 名称粗判；③默认档为「高」。本单只做「参数表 + 检测 + 档位切换管线」，具体渲染特性（体积雾、CSM、描边等）在 023–026 实现，它们从本表读参数。

## 具体内容
1. `QualityPreset` 补齐 style-guide §8 表中**全部键名**（`heroCharTris` 高档按裁定第 4 条为 50k；`renderScale`、`maxPixelRatio`、`heroCharTris`、`npcCharTris`、`sceneVisibleTris`、`maxDrawCalls`、`textureMaxSize`、`textureMaxSizeEnv`、`anisotropy`、`outlineHull`、`outlinePost`、`fogMode`、`fogCards`、`lightShafts`、`softParticles`、`rainParticles`、`shadowType`、`pointLightShadows`、`ao`、`reflections`、`dof`、`bloom`、`lut`/`toneMapping`、`filmGrain`/`vignette`、`antialias`、`lodDistances`、`impostorDistance`、`grassDensity`），数值逐项照抄 §8；另加本单第 4 条的 `viewDistance`（600 / 400 / 250 m）。现有字段（`shadowMapSize`、`rainCount` 等）与 §8 冲突的以 §8 为准（例如雨粒子 极致 30k / 高 15k / 标准 6k，阴影 4096 / 2048 / 2048）。
2. **默认档改为极致**。删除按 GPU 名称判档的逻辑（可保留为日志信息）。
3. **画质自动检测**（style-guide §8；拆单裁定第 5 条（`docs/releases/v0.1.md`「拆单裁定」）；制作人裁定 2026-10-29）：
   - **首次启动后第一次进入 S1 时跑一次**：设置里 `qualityDetected=false`（新安装/清空设置）时触发；之后不论重启还是再次进入 S1 都不再检测。
   - **每轮 3 秒，最多 3 轮（共约 9 秒）**：第 1 轮测极致档，平均 < 50 fps 降到高档；第 2 轮测高档，仍 < 50 降到标准档；**第 3 轮只测标准档并记录结果，不再往下降**（已裁定，制作人 2026-10-29；最多连降两档：极致 → 高 → 标准）。第 1、2 轮 ≥ 50 fps 就停止，档位定为这一轮的档位。切档后重建资源的那几帧不计入平均。
   - **第 1 轮在开场演出内完成**：检测窗口是开场演出尾段的 9 秒（035 预留，最后 3 s 是 S1 建立镜头），正常播放时三轮都在演出里跑完。**降档后的重测（第 2、3 轮）可以在玩家可操作后继续**，后台跑完，不打断操作、不弹提示。
   - **第 1 轮完成前跳过开场演出（已裁定，制作人 2026-10-29）**：跳过后保留 3 s **不可跳过**的 S1 建立镜头跑第 1 轮；镜头播完停在最后一帧，第 1 轮仍未完成就最多再等 5 s；5 s 到了不论测没测完都交还控制，没测完的第 1 轮在玩家可操作后接着测完，不作废。这和 BUG-002 修复后的实现一致（`CameraTrack.holdUntil` + `maxHold` 默认 5 s，S1 用 `benchmark.firstRoundDone`）；跳过后的这 3 s 要设成不可跳过（`skippable: false`）。
   - 检测中每次降档都走正常的切档流程（`quality:changed`，`source: 'auto'`）；全部结束后发布一次 `quality:detected`（`{ tier, drops, rounds: [{ tier, fps, simulated }] }`）。
   - 结果写入设置（006，`qualityDetected=true`、`qualityTier`）。玩家在设置里**可以随时手动改回**任意档位；手动改过后不会再被自动改动。降过档时设置界面在画质项下显示 `ui.settings.quality_auto_note`。
   - 「恢复默认」不重新检测，画质回到检测结果。
4. **档位切换**：运行时切换不重载场景；需要重建的资源（阴影贴图、渲染目标）在切换时重建。统一发布 `quality:changed`（`{ tier, previous, source: 'user' | 'auto' | 'settings' }`），渲染、后处理、场景各自监听它更新。**切档不能有可见黑帧**：新资源准备好之后再换上，切换前后画面连续（只允许画质本身的变化）。
   - **视距**（新增键 `viewDistance`，即相机远裁剪面 `camera.far`；制作人裁定 2026-10-29，style-guide §8 表里没有这一项，以本单为准）：**极致 600 m / 高 400 m / 标准 250 m**，收到 `quality:changed` 立即生效。远景剪影和雾墙贴片要放在 250 m 以内（或放在不受远裁剪面影响的天空层），保证三档构图一致（018、024）。
5. 开发模式性能面板（F3 扩展）：FPS、帧时间、draw call、三角面数、显存估算（`renderer.info`），用于对照 §8 预算。

## 验收标准
- [ ] `quality.ts` 包含 style-guide §8 表中所有键，三档数值与表完全一致（`verify-quality.mjs` 通过）。
- [ ] 清空设置后（视为首次启动）第一次进入 S1：第 1 轮检测在开场演出内完成；完整播放演出时三轮都在演出尾段 9 s 内跑完。
- [ ] 用 `?simulateFps=40` 模拟低帧率：自动降到「高」，重测后再降到「标准」，第 3 轮只测标准档并记录，不再往下降；三轮共约 9 s，结束后只发一次 `quality:detected`。
- [ ] 在第 2 轮开始前跳过开场演出：剩下的重测在玩家可操作后继续跑完，期间移动和视角不卡、不弹提示；在第 1 轮完成前跳过：跳过后播放 3 s S1 建立镜头，期间按住空格不能再跳；镜头播完停在最后一帧等第 1 轮测完，最多再等 5 s 后交还控制（超时也会交还，没测完的第 1 轮之后接着测完）。
- [ ] 检测后刷新页面、重新启动都不再检测；设置里手动改回极致后生效并保存，之后不被自动改动。
- [ ] 默认（无设置、无检测结果）档位为极致。
- [ ] 运行时切换三档（手动切换和自动降档）不崩溃、**没有可见黑帧**：60 fps 录屏逐帧检查，切换前后没有整帧黑屏、白屏或空帧；切换时单帧卡顿 < 100 ms。
- [ ] 三档视距分别为 600 / 400 / 250 m（`camera.far` 读 `viewDistance`），切档后立即生效；`quality:changed` 带 `tier`、`previous`、`source`。
- [ ] F3 性能面板显示 FPS、帧时间、draw call、三角面数。
