# v0.1-014 S2 白石组观察点数据（给美术 021 白石组）

数据取自游戏代码 master 92c7c96（2026-10-30）。下面的数值是现在游戏里实际运行的值，美术回复 1030 第 5 条要的数据也在这里。

## 0. 坐标系

- **全部数值都是 S2 局部坐标，也就是崖顶局部坐标。** S2 场景根节点不做变换，谜题判定、白盒、相机都在这个坐标系里算。
  - 轴向：+Y 上，+Z 北，右手系，所以东 = −X、西 = +X。
  - 单位是 m。崖顶平台地面 y = 0，崖底 / 海面 y = −16。
- **env-clifftop-s2 的摆放是 translation [0,0,0]、rotationY 0**（`src/levels/s2/layout.ts:127`，与 s2-layout.json 一致）。所以「崖顶 GLB 局部坐标 = S2 局部坐标」，两者一模一样。
  - 白石模型按 `artSlots` 挂在 env-clifftop-s2 根下：`src/levels/s2/artSlots.ts:7,23`，`at: ['env-clifftop-s2','white-stones-s2']`。挂上后白盒石块会隐藏。
  - 白石模型直接用本文的坐标即可。
- **s2-layout.json**（art/source/env）：
  - `points.viewpointS2`（第 173 行）的 eye / lookAt / fov 与游戏完全一致，误差为 0。
  - `stonesArea`（第 187 行，GLB extras 里也有一份）是 x 14–22、z −2.5–4.5、center [18,0,1]。lookAt 的水平位置就是这个 center。
  - `placeholders.whiteStones`（第 320 行）的 8 个点与游戏白盒逐个相同。
  - json 里写着 `placeholder: true`，现在可以视为已确认：014 白盒采用了这套值。
  - 以后两边冲突以 `layout.ts` 为准（`layout.ts:5` 注释）。
- **美术参考节点 `env-keeper-house-ch1-interior-viewpoint-s2-ref`**：
  - GLB 局部坐标 (2.95, 4.35, 0)，加上 interior 摆放 (−2, 0, 1)，得到 S2 坐标 (0.95, 4.35, 1.0)。
  - 四元数与游戏 `viewpoint-s2` 节点相同（只差一个整体符号，表示同一个朝向）。这个参考节点可以继续用。
- **世界坐标（S1/S3 共用）**只影响远景对位，白石摆放用不到：
  - `S2_WORLD_FRAME`（`layout.ts:148-163`）：world = origin + R_y(120°)·local。
  - origin 由「S2 入口 (0,0,−12.5) 落在 S1 出口 (−9.6, ·, 21)」解出，y = +16。
  - 下文的世界坐标都用 `s2ToWorld` 算出。

### 1.1 实际摄像机位置（重要）

游戏用的是第三人称相机，判定拿的是**相机的实际位置和实际朝向**，不是 eye 点。eye 是角色头部，也就是跟随点。规则在 `src/systems/CameraFollowSystem.ts:261-311`：

- 跟随点 = 脚底 + 1.35（`gameplay.ts:69`）。
- 在此基础上向右偏 0.4 m（`gameplay.ts:71`）。
- 二层在 `s2-house-indoor` 室内体内，相机臂长上限 2.0 m（`gameplay.ts:87`）。

把视线对准 lookAt 时（做法与 smoke 观察点用例相同，`scripts/smoke-browser.mjs:490-504`），用白盒物理加碰撞实际算出：

| 项 | 值 |
|---|---|
| 相机位置（S2 局部） | **(−0.983, 4.823, 1.445)**，即离地板 1.82 m，位于 eye 东侧约 1.9 m（屋内），偏北 0.45 m |
| 相机世界坐标 | (2.969, 20.823, 14.879) |
| 相机 yaw / pitch | **yaw −88.66°，pitch −13.68°** |
| 朝向向量 | **(0.971, −0.237, −0.023)** |

yaw 的约定：forward = (−sin yaw·cos pitch, sin pitch, −cos yaw·cos pitch)；yaw 0 朝 −Z（南），−90° 朝 +X（西）。

- 透过西窗取景：二层西窗洞口在 x = 2（外墙）处，z 0.55–1.45、y 3.9–5.1（`layout.ts` 的 `openings.winW2`）。上面这条视线穿过外墙时约在 z 1.37、y 4.10，在洞口内。
- 建议美术做透视拼合时以**相机实际位置 (−0.983, 4.823, 1.445)** 为准，FOV 30°。
- 如果要按「眼睛」设计，就用 eye (0.95, 4.35, 1.0)。两者看 lookAt 的方向只差约 1.3°，在 6° 容差内。但从两个位置看到的视差不同：近处石块（15 m）的视差大约在 1° 量级。
- 也可以改游戏，让观察模式切成第一人称（相机放到 eye）。现在没做，需要的话另开单。

## 3. 对准后应呈现的图案

- **图案是三个数字「3 1 7」，从观察点看从左到右排列。** 观察点朝西，所以左到右 = 南到北。
- 这串数字就是北侧拨盘铁门的密码：`S2.dialGate.code = [3,1,7]`，三个拨盘从西到东（`layout.ts` 的 dialGate）。
- 对准（≤ 6°）后播放独白 `ch1.s2.white_stones.mono_digits`（「三，一，七。」）。

现在的程序占位（`src/levels/s2/puzzles.ts:470-484`，七段数字见 `src/levels/s2/digits.ts:20`）：

- 节点 `white-stones-s2-digits`，标记 puzzleCritical，不透明度等于对准度。
- 七段数字：字高 **2.2 m**，字宽 1.21 m（0.55 h），笔画粗 0.352 m（0.16 h）；字间距（中心距）**1.9 m**。
- 整组中心在 (18, 1.3, 1)，也就是 lookAt 往上 1.1 m，正面朝 eye（group.lookAt(eye)）。
- 各字中心（S2 局部）：
  - 「3」 (18, 1.3, −0.9)，南
  - 「1」 (18, 1.3, 1.0)
  - 「7」 (18, 1.3, 2.9)，北
- 从 eye 看，单字高约 7.3°，三字总宽约 16.5°。30° FOV 下整组大约占画面高度的 1/4、宽度的 1/3（16:9）。
- artSlots 的约定是「3 1 7」渐显继续由程序做（`artSlots.ts:7`）。如果美术用石块透视拼合成数字（石块在别的角度看是散的，从观察点看拼成「3 1 7」），交付后可以关掉程序贴片，改为按对准度提亮石块材质。这需要另开单确认。
