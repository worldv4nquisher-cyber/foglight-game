# v0.1-001 输入层与键位改造

- **负责人**：程序
- **里程碑**：M4
- **依赖**：无
- **工时估算**：1–1.5 人日

## 背景
GDD §3（操作方式）、§15（不做跳跃、手柄、点击寻路）。现有框架 `src/systems/input/`（actions.ts、InputManager、KeyboardMouseInput、TouchInput）已有抽象 action 层，但键位是 demo 用的：有 `jump`、默认拖拽转视角（`gameConfig.input.pointerLock=false`）。

## 具体内容
1. `actions.ts` 按 GDD §3 重定义 action（保留抽象层，后续接手柄只需加绑定）：
   - 轴：`moveX` / `moveY`（WASD + 方向键，保留）。
   - 按钮：`sprint`（Shift 按住小跑）、`interact`（E）、`partPrev` / `partNext`（Q / E，仅机关模式）、`partWheel`（滚轮，机关模式切换部件；探索模式调相机距离）、`observe`（鼠标右键按住）、`exitPuzzle`（鼠标右键单击 / Tab，机关模式与阅读界面）、`fineAdjust`（Shift，机关模式精调，与 sprint 复用同键、按上下文区分）、`resetPuzzle`（R）、`hint`（H）、`journal`（J）、`pause`（Esc）、`advance`（鼠标左键 / Space 推进字幕）、`skipHold`（按住 Space 1 秒跳过演出）、`toggleFps`（F3，仅开发/设置开启时）。
   - 删除 `jump` 及其所有引用（PlayerController、TouchInput 的「跳」按钮、README 操作表）。
2. 指针锁定默认开启：`gameConfig.input.pointerLock = true`。点击画面进入锁定；锁定丢失（浏览器 Esc）一律进入暂停菜单（沿用现有 `game:pause{reason:'pointerlock'}`）。
   - **注意浏览器限制**：指针锁定状态下按 Esc 由浏览器处理、页面不一定收到 keydown，且退出后约 1 秒内不能重新锁定。所以「退出机关 / 关闭阅读」**主键用鼠标右键或 Tab**，Esc 始终是「暂停」。此为制作人拆单裁定第 3 条（`docs/releases/v0.1.md`「拆单裁定」）：GDD §3 / §10 中的「Esc 退出机关 / 关闭阅读」一律按此实现。机关模式按键提示条显示「右键 退出」，阅读界面显示「右键 关闭」，文案用 `docs/gdd/text-ch1.md` 的 `ui.prompt.puzzle_bar`、`ui.prompt.reader_bar`。
3. 输入上下文（context）栈：`explore` / `puzzle` / `reading` / `cutscene` / `menu`。同一按键在不同上下文映射不同 action（E 在 explore = 交互，在 puzzle = 下一个部件；右键在 explore = 观察，在 puzzle/reading = 退出）。提供 `input.pushContext()/popContext()`。
4. 鼠标灵敏度、Y 轴反转从设置读取（设置存储见 006），提供 `input.setLookSensitivity()`、`input.setInvertY()`。
5. TouchInput 保留代码但默认不注册（桌面专做，GDD §15）。

## 验收标准
- [ ] 代码中搜索不到 `jump` action；空格不会让角色跳起。
- [ ] 进入游戏点击画面后鼠标被锁定，鼠标移动直接转视角，无需按住。
- [ ] 按 Esc：鼠标解锁并弹出暂停菜单；点「继续」后再次点击画面可重新锁定。
- [ ] GDD §3 表中每个按键在对应上下文都能触发对应 action（开发模式下控制台或 HUD 调试面板可看到 action 名）。
- [ ] 机关上下文中按 E 不会触发「交互」，而是切换部件；右键 / Tab 退出机关回到 explore。
- [ ] 鼠标灵敏度、Y 轴反转修改后立即生效。
- [ ] `npm run check` 通过。
