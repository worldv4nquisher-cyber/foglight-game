## 背景
GDD §14（光照策略：静态环境烘焙光照贴图 + 光照探针，动态灯光实时）。style-guide §3.1（烘焙：Blender 烘好后导出 lightmap，实时光只负责角色、动态物体和暖光；时段预设）、§8（`ao`：三档都用烘焙 AO）。

## 具体内容
1. 用 Blender 按场景烘焙光照贴图（只含阴天天光 + 主方向光的间接光和 AO，**不烘任何暖光**，暖光都是实时）：
   - S1 `overcast-dusk`、S2 室外 `overcast-after-rain` + 室内单独一张、S3 室外 + 塔内单独一张。
2. 输出：`tex-<场景或对象>-lightmap.ktx2`（如 `tex-s1-ebb-shore-lightmap.ktx2`、`tex-keeper-house-ch1-interior-lightmap.ktx2`），2048，HDR 用 KTX2 UASTC 或 RGBM 编码（与程序约定）。
3. 光照探针：每个场景导出 SH 探针数据（或由程序在引擎里烘，二选一与程序商定，写进交付说明）。
4. 潮汐相关区域：只烘退潮时露出的地面；水下部分 AO 弱化，避免涨潮后出现不合理暗斑。

## 编码定案（程序，2026-10-30，依裁定 18 ②）

**采用 RGBM（范围 8），装进 KTX2 UASTC（LDR）。不用 UASTC HDR。**

- 编码：线性 HDR 值 `L`（烘焙输出，未做色调映射）→ `M = clamp(max(L.r,L.g,L.b)/8, 1/255, 1)`，`M` 向上取到 1/255 的整数倍，`RGB = L/(8·M)`，A = M。存线性数据，**不要**标 sRGB（KTX2 transfer = linear）。
- 压缩：`toktx --t2 --uastc 3 --uastc_rdo_l 1.0 --zcmp 19 --genmipmap --linear --assign_oetf linear`（或 basisu 等价参数），保留 alpha，2048²。预计每张 1.5–2.5 MB（zstd 后），每场景 1–3 张。
- 程序解码：`rgb · a · 8`，在光照贴图采样处用 onBeforeCompile 替换；强度系数仍按交付说明的 `lightMapIntensity` 乘。
- 为什么不选 UASTC HDR：浏览器需转成 BC6H 或 ASTC HDR。Safari / 部分 Mac 设备不一定支持，回落到半精度未压缩时，一张 2048² 显存约 32 MB，还要重做转码链；RGBM + UASTC 在所有桌面浏览器（含 Safari）都转成 BC7/ASTC LDR，包体和显存都可控。
- 画质注意：亮度超过 8（直射高光）会被截断，烘焙时直射光可正常截断；暗部 alpha 下限 1/255 防止色偏。请美术交付时附一张同场景 EXR 预览或 PNG 截图，我对比解码结果。
- 交付说明需写：编码 = RGBM8、lightMapIntensity、UV2 通道名（默认 `uv1` / glTF TEXCOORD_1）。
