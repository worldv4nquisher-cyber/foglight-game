# v0.1-010 场景流程、分包加载与切换

- **负责人**：程序
- **里程碑**：M4
- **依赖**：006、008
- **工时估算**：2.5–3 人日

## 背景
GDD §10（启动分两段加载）、§14（加载：主菜单包 ≤ 15 MB 且 3 秒内出现；首场景包 ≤ 150 MB；S2/S3 后台流式预加载；黑场 1.0 s 内完成切换；字体子集化 WOFF2）、§4（场景切换黑场 1.0 s + 3 秒建立镜头）。现有 `SceneManager`（Boot → Loading → Main）、`manifest.ts`（按 group 加载）、`LoadingScreen` 可直接扩展。

## 具体内容
1. 场景注册：`menu`、`s1-ebb-shore`、`s2-keeper-house`、`s3-lighthouse`（demo `MainScene` 保留为 `sandbox`，仅开发模式可进）。
2. manifest 分组：`boot`（加载页最小资源）、`menu`（主菜单 + UI + 字体）、`common`（主角、风灯、通用材质/音效，随首场景加载）、`s1`、`s2`、`s3`。
3. 加载流程：
   - 启动只加载 `boot` + `menu` → 主菜单。
   - 「新游戏」：加载 `common` + `s1`（加载页显示进度，即「首场景包」）→ 开场演出（035）→ S1。
   - 「继续」：加载 `common` + 存档场景组。
   - 进入 S1 后后台加载 `s2`；进入 S2 后后台加载 `s3`；离开场景时释放上一场景资源（`dispose`）。
   - 走到场景出口：黑场 1.0 s；若下一场景尚未加载完，在黑场中显示细线进度，加载完再淡入。黑场中写存档（006）。
4. **包体检查脚本**：`npm run size` 统计每个组的文件总大小（按 manifest 计算 dist 内实际文件），`menu` > 15 MB 或 `common+s1` > 150 MB 时报错退出；并入 `npm run check`。
5. 字体：思源宋体/思源黑体按文本表实际用字子集化为 WOFF2（构建脚本，读取 `content/text/zh-CN.ts`）。
6. 场景出口：`SceneExit` 触发体组件（目标场景 id、入口点 id）；每个场景有命名入口点 `-spawn-<id>`。

## 交付物

- `game/src/assets/manifest.ts`（分组）
- `game/src/entities/components/SceneExit.ts`

## 验收标准
- [ ] 本地 `npm run preview`，Chrome 网络限速「Fast 4G 关闭 / 普通宽带 50 Mbps」下，从打开页面到主菜单可操作 ≤ 3 秒（DevTools Performance 记录）。
- [ ] `npm run size` 输出各组大小，`menu` ≤ 15 MB、`common+s1` ≤ 150 MB，超限时命令失败。
- [ ] 新游戏 → S1 有进度条；S1 → S2、S2 → S3 切换黑场 ≤ 1.0 s（后台预加载已完成的情况下）。
- [ ] 模拟慢网速时，黑场中显示进度且不会出现未加载完的场景。
- [ ] 场景切换后上一场景的几何体/贴图被释放（`renderer.info.memory` 回落）。
- [ ] 字体文件为 WOFF2 子集，单个字体文件 ≤ 2 MB。
