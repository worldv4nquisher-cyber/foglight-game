# tex-*-ramp 256×1 KTX2 → 0x502 调查（10-31，执行者，只查不修）

## 现象
check:release 的 verify-budget 在 s1/s2/s3 进场加载时记到 WebGL INVALID_OPERATION（0x502），来源是 4 张 ramp：
tex-xi-ramp / tex-ramp-char / tex-ramp-env / tex-ramp-metal-wet（common 组）。
文件头：256×1，9 级 mip（256×1 … 1×1），supercompression = zstd（**UASTC**），每张约 1.1 KB。

## 桌面上会选哪种格式（three r186 KTX2Loader，UASTC 的优先级）
ASTC 4×4 > **BC7（BPTC）** > ETC2 > ETC1 > BC3（S3TC）> PVRTC > RGBA32 未压缩
- Windows Chrome / Edge（ANGLE D3D11）：没有 ASTC，有 BPTC → **BC7**
- Intel Mac：BPTC → **BC7**；Linux 桌面：KTX2Loader 主动关掉 ASTC / ETC（Mesa 软解）→ **BC7**
- 只有 S3TC 没有 BPTC 的老显卡：BC3 / BC1，限制相同
- Apple Silicon Mac（ANGLE Metal 暴露 ASTC）、安卓 / iOS：ASTC 或 ETC2 → 不受影响（这两种扩展没有「4 的倍数」限制）

## 桌面真机会不会黑
会，而且和显卡厂商 / 驱动无关：
- 限制在 **WebGL 层**（浏览器校验，不是驱动）：EXT_texture_compression_bptc 和 WEBGL_compressed_texture_s3tc 都规定
  「`width << level` 和 `height << level` 必须是 4 的倍数，否则 INVALID_OPERATION」。256×1 的 0 级高度 1 → 每一级上传都被拒。
  （https://registry.khronos.org/webgl/extensions/EXT_texture_compression_bptc/ 、…/WEBGL_compressed_texture_s3tc/；
  ASTC 扩展只校验字节数，所以 ASTC 设备没事）
- 上传全失败 → 纹理不完整 → WebGL2 规定不完整纹理采样返回 (0,0,0,1)。box 上的 swiftshader 走的是同一套 Chrome WebGL 校验，和真机行为一致。
- 实际画面影响（目前只有 tex-xi-ramp 被着色器采样，另外 3 张「接上之前只下载不使用」）：
  xiMaterials.ts 里 `lit = texture2D(uXiRamp, …).r` 恒为 0 →
  汐的身体 / 头发直射漫反射 = 全部按暗部冷色（XI_SHADOW_TINT），没有明暗分界，直射高光乘 lit 也全没了；
  脸走 SDF 分支，不受影响。不是纯黑，是「整个人一直在阴影里、发灰发冷、无高光」（XI_SHADOW_TINT = 0.30 / 0.34 / 0.42，直射只剩约 1/3、偏蓝）。
- 对照截图（box 上拍的，box 同样选 BC7 → 同样失效）：shots-031/s1-xi-face-front.png 脸上鼻侧有硬边 SDF 阴影 → 脸的卡通明暗生效；
  s1-xi-cuff-side.png 外套整片均匀暗蓝，只有贴图 / AO / 环境光的柔和起伏，没有 ramp 应有的明暗硬分界，也没有直射高光 → 身体 / 头发的 ramp 明暗**没有生效**。
  → 到目前为止所有 box 截图里的汐身体都是「坏掉的样子」，美术 / 制作人据此调过的观感也是在这个前提下；制作人 Windows / Intel Mac 桌面上同样如此（控制台 / Spector.js 可见 0x502）。
- 另：KTX2Loader 对 9 级 mip 设 LinearMipmapLinear，即使能上传，ramp 在轮廓处也会取到糊掉的小 mip。
- 另 3 张接上之后（父亲 toonRamp、023 环境三渲二）会同样失效。

## 修法候选
| | 做法 | 谁改 | 代价 / 风险 |
|---|---|---|---|
| A | 加载时这几张强制转码成未压缩 RGBA32：单独一个 KTX2Loader 实例，detectSupport 后把 workerConfig 的 astc/bptc/dxt/etc/pvrtc 都设 false（UASTC 会回落到 RGBA32），manifest 给 ramp 标 `uncompressed: true` 走它；或通用规则「宽高不是 4 的倍数的 KTX2 一律走它」 | 程序 | 每张 256×1×4 B ≈ 1 KB 显存，可忽略；不动美术、包体不变；多一个转码 worker（可共用池）。通用规则顺带防以后再出同类文件 |
| B | 美术重新导出 256×4（4 行相同），仍 UASTC | 美术 | 着色器 v=0.5 不用改；BC7 / BC3 都合法；包体 +几百字节。以后新 ramp 都要记得 4 的倍数 |
| C | ramp 改成 PNG（type: 'texture'，256×1 RGBA8，NoColorSpace / 线性过滤 / 不要 mip） | 美术 + 程序（manifest 一行 + 采样参数） | 最直观，~1 KB；不走 KTX2 管线；美术照常在图上改 |
| C′ | 程序里用 DataTexture 生成 ramp（美术给关键点 / 曲线写进配置） | 程序 | 零下载、零转码；美术改 ramp 要改配置而不是改图，流程变了 |
| D | 不管选哪个，都建议 ramp **不要 mip**（9 级 mip 在轮廓处会按导数取到糊掉的级，明暗分界变软），并在 verify-assets 加「KTX2 宽高必须是 4 的倍数」检查 | 程序 | 防回归 |

执行者倾向：A（通用规则）+ D 立刻能做、不依赖美术；B / C 作为美术侧的长期规范。由制作人和美术定。
