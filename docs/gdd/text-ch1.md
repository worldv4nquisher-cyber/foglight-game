## 0. 写作与显示约定

1. **口吻**：只有两种声音——汐的内心短句（第一人称，克制，不解释情绪）和父亲的文字（日志、纸条、目标）。**没有旁白，没有配音**（GDD §13）。
2. **第一章不点破**：父亲已不在、汐将成为守灯人只在两处留伏笔——日志末页「如果灯一直没亮，就由你来点。」、没寄出的信被划掉的后半段。灯室纸条「没有火的时候，就借光。」不署名。汐自己的台词不承认、不追问。
3. **少**：全章汐的独白 17 句，大部分「只触发一次」。宁可沉默。
4. **显示时长**：「自动 Xs」= max(2.0 s, 字数 × 0.12 s)（GDD §9，标点不计入时可略短，程序按实际算法），玩家可左键/Space 提前推进；演出中的字幕用表中给定时长、演出锁定。
5. **字幕样式**：底部居中、无底框、浅阴影（style-guide §6）；汐 = 正文色 `#E4E8EA`，父亲的文字（目标）= 次要色 `#8B959D`；不显示说话人名字。
6. **同一时刻只显示一条**：新字幕到来时，独白/查看会顶掉旧的；演出字幕优先级最高，演出期间屏蔽独白与查看。
7. **「只一次」**：标注「只一次」的条目，触发记录存进存档（已读 ID 列表复用 `readDocs` 字段或新增 `seenLines`，由 005/006 决定）。读档回到场景入口时不重复触发已触发过的独白。
8. **ID 规则**：`ch1.<场景>.<对象>.<类型>`（对象名与关卡/资源 id 一致，如 `tide_bell` ↔ `tide-bell-s1`）；提示 `ch1.hint.p<n>[.<步骤>].l<1-3>`；跨章 UI 用 `ui.*`，交互提示词 `ui.prompt.*`。ID 一经程序引用不再改名，改文案只改 text。
9. **占位符**：`{time}`、`{count}`、`{producer}` 等由程序替换。
10. **查看（inspect）类**：按 E 后以字幕显示一句汐的描述，不打开阅读界面（需 004 支持 `inspect` 交互类型，已同步到任务单 004）。

## 11. 给程序：JSON 结构与转换

`docs/gdd/text-ch1.json`：

```json
{
  "meta": { "chapter": "ch1", "title": "第一章 · 归岸", "locale": "zh-CN", "version": 1, "count": 179 },
  "strings": {
    "ch1.intro.line_home": "爸爸说，灯不亮的时候，就自己回家。",
    "ch1.s2.journal.doc": ["十二月三日，雾。\n\n……", "……"]
  },
  "entries": [
    { "section": "intro", "id": "ch1.intro.line_home", "type": "subtitle", "speaker": "xi",
      "text": "……", "trigger": "……", "duration": "4.0s（演出锁定，不可手动推进）", "note": "……" }
  ]
}
```

- `strings`：运行时只需要这一段。值为字符串，或字符串数组（多页文档，一页一项）；`\n` 为换行。
- `entries`：附带类型、说话人、触发条件、时长建议，供关卡脚本和测试对照，不必打进运行时包。
- `type`：`subtitle` 演出字幕｜`title` 标题卡｜`monologue` 独白｜`inspect` 查看｜`goal` 当前目标｜`journal` 父亲日志｜`doc` 其他文档｜`hint` 提示｜`prompt` 交互提示词｜`ui` 界面。`speaker`：`xi`｜`father`｜`none`｜`system`（决定字色，见 §0.5）。
- 字体子集化（任务单 010）直接扫描 `strings` 所有值即可覆盖本章全部用字。
- 改文本：策划同时改本文件和 JSON（同一数据源生成）；程序发现 ID 缺失或想加新 ID，在本文件 §12 下留言，不要在代码里写死中文。
