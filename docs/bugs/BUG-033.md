# BUG-033 音频上下文 resume / suspend 的 Promise 没接住；首次解锁失败后不再重试（低）

- 发现：程序 M7 兼容测试（playwright Firefox 157 跑 smoke:xb，刷新那一步）+ 代码审查
- 平台：所有浏览器；Firefox 刷新 / 离开页面时必现控制台报错
- 复现：Firefox 打开游戏，不点任何地方（AudioContext 处于 suspended、resume 挂起）→ 刷新。控制台出 `InvalidStateError: Navigated away from page`（未处理的 Promise rejection）。
- 期望：控制台无报错；首次手势没能解锁音频时，下一次手势继续尝试。
- 实际：
  1. AudioSystem 的 unlock / suspend / resume 都是 `void ctx.resume()` 之类，Promise 被拒（Firefox 页面卸载、Safari 非手势 NotAllowedError、上下文已关）时成为未处理 rejection；冒烟口径下算错误。
  2. unlock 不管 resume 成没成功都撤掉 pointerdown / keydown / touchend 监听。万一第一次手势没解锁成功（例如 Safari 对某些按键不算用户激活），整局都不会再试，游戏没声音。
- 严重度：低（玩家不可见的控制台报错；2 是潜在无声，没在真机上复现过）
- 修法：接住 rejection；resume 之后上下文真的变成 running 才撤监听，失败下次手势再试；suspend / resume 也接住。verify-audio 加单测（假上下文 resume 先拒后成，断言无未处理 rejection、监听保留 / 撤除时机）。
- 状态：已修（程序 M7，commit 3a8b4a3），QA batch24 回归通过，已关闭。真机 Safari 确认项写在 v0.1-compat-report「需要用户在真机上确认」。
