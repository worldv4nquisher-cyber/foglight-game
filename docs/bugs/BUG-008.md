# BUG-008 冷启动时字体首个请求仍会被取消（attempts=2）

- **关联单号/commit**：batch4 附带项（字体只下一次）的修复 1f7d469，在 master 4f672e9 快照上复现。代码位置：src/assets/fontLoader.ts、AssetLoader.ts:255。
- **发现**：QA batch5，2026-10-29 约 20:03（UTC+7）。
- **严重度**：轻微。最终每个字体只成功下载 1 次，被取消的那次传输 0 B，玩家只会感觉字体晚出现约 0.33 s（重试等待），画面和功能都正常。

## 环境
- HeadlessChrome/156.0.0.0，Linux x86_64。
- 每次新开 Chrome，用全新的临时 user-data-dir，所以是冷缓存。
- `vite preview` 跑构建产物，地址 http://127.0.0.1:<port>/?smoke=1。
- SwiftShader 软件渲染；当时机器负载 load avg 约 14.7。

## 复现步骤
1. 新开一个 Chrome profile，开启 CDP Network 记录。
2. 打开 `/?smoke=1`，等主菜单出来。
3. 读 `__game.assets.fontStats`，同时看 Network 里的 woff2 请求。

## 期望
冷启动时每个 woff2 只发 1 次请求，attempts=1，没有被取消的请求。

## 实际
- 3 次冷启动里有 2 次（端口 5266、5267），两个字体的第一个请求都是 `net::ERR_ABORTED`、canceled=true、没有收到响应。约 0.33 s 后发出第 2 个请求，得到 200，fontStats 显示 attempts=2、ok=true。performance 里每个字体都有一条 transferSize 0 的条目，外加一条完整下载的条目。
- 第 3 次（端口 5268）attempts=1，没有取消。
- 两个字体总是同时被取消（requestWillBeSent 时间戳一样），看起来是同一个外部原因导致的中止，不是网络问题。
- 原始数据：/tmp/t5-font.log。测试脚本：/workspace/qa-tools/t5-font.mjs。

## 截图
- docs/bugs/qa-v0.1-batch5/font-cold-5266.png（attempts=2 那次，菜单显示正常）

## 修复说明
- 修复提交：game/ 仓库 `641e1c8`（只改 `src/assets/fontLoader.ts` 的注释，写明根因）。游戏代码不需要改，现有重试（`FONT_RETRIES = 2`，间隔 150 ms）保留。
- 根因：**测试环境问题，不是游戏代码。** 测试机 Chrome（/usr/bin/google-chrome）有托管策略 `/etc/opt/chrome/policies/managed/sand-webauthn.json`，它的 `ExtensionSettings` 会往每个新建的 profile 里强制安装两个扩展：`mdjdbbecjiocafgiojaalonedjcehkck`（sand-webauthn-proxy）和 `mbonmaifbffecnmcgiecijopmdamfdki`（1Password）。冷启动时扩展正在安装或激活，页面的子资源加载器会被重建（这一步是推断的机制），正在进行中的 fetch 就被浏览器内部取消了。两个字体同时被取消，也是因为这个原因。
- 证据（探针脚本在 docs/bugs/BUG-008-probe/：font-probe.mjs、cdp2.mjs、b5lib2.mjs）：
  1. 不降速：大约每 5～8 次冷启动出现 1 次 attempts=2。
  2. CDP 把 CPU 降速 8×：11/12 次 attempts=2。同时关掉 DevTools Network 域（NONET=1）：8/8，说明和 CDP 的网络记录无关。
  3. 加 `--disable-extensions` 后，同样 CPU 降速 8×：0/6。
  4. 不带游戏代码的最小页面（同一种 fetch 写法）复现不了，问题和扩展初始化的时机有关。
  5. net-log 里只有重试那一次的 URL_REQUEST，第一次请求根本没到网络服务，是在浏览器里就被取消了。JS 一侧拿到的是 TypeError「Failed to fetch」。页面里也没有调用 AbortController.abort 或 window.stop（用 init-script 挂钩确认过）。
  6. 字体 fetch 是在 readyState=interactive 时发出的，取消发生在 load 事件后约 10～120 ms，这个时间点和 chrome.log 里 1Password 扩展初始化的时间对得上。
- 改动：只补了注释。真实玩家的浏览器里也可能有扩展造成同样的取消，所以重试不能删。重试成功时界面没有任何异常，fontStats 会显示 attempts=2、ok=true。
- 回归：`npm test`（包含字体子集和字体加载器的用例）通过。重试路径保持原样。
- 遗留 / 建议：QA 冷启动测字体请求次数时，启动参数加 `--disable-extensions`（或者用不受这条策略影响的 Chrome），否则「每个 woff2 只请求 1 次」这条期望会随机失败。要不要把这个参数写进 QA 脚本，请 QA 决定。

## 回归（QA batch7，2026-10-29 23:2x UTC+7，master ed61faf 快照）
- 状态：**关闭**（根因确认是测试环境，游戏重试有效）。
- 脚本：/workspace/qa-tools/t7-font.mjs，CPU 降速 8×，每次新 profile 冷启动。日志：/tmp/t7-font.log。
  - 不加参数：6/6 次 attempts=2，每次 2 个 woff2 首次请求是 net::ERR_ABORTED（canceled），重试后 ok。
  - 加 `--disable-extensions`：0/6 次重试，0 个请求被取消。
- 以后 QA 冷启动测字体请求次数时，都加 `--disable-extensions`。
- 附带发现：同一个取消窗口也会打到 KTX2 贴图上，而贴图没有重试，见 BUG-012。

## 回归结论（QA batch7 收尾，2026-10-30 UTC+7）
- 状态：**已关闭**。641e1c8 的根因结论已复现确认（不加 --disable-extensions 时 6/6 首个字体请求被取消、加上后 0/6），游戏重试有效，字体最终各只下载 1 次。同一触发源导致的 KTX2 贴图问题另开 BUG-012。 详见 qa-v0.1-batch7.md §4b。
