# BUG-012 冷启动时 KTX2 贴图请求被浏览器取消后不重试，对应模型整局没有贴图

- **关联单号/commit**：v0.1-013 美术外部 KTX2（GLTFLoader 按 GLB 里的 `../../textures/*.ktx2` 去加载）；和 BUG-008（641e1c8）是同一个触发源。在 master ed61faf 快照上复现。代码位置：src/assets/（只有 fontLoader.ts 有重试，GLB 和 KTX2 贴图都没有）。
- **发现**：QA batch7，2026-10-29 23:0x–23:2x（UTC+7）。t7-s1.mjs 的控制台出现 `THREE.GLTFLoader: Couldn't load texture ../../textures/tex-sand-tidal-*.ktx2`，之后专门做了冷启动对比。
- **严重度**：一般（不卡流程，但码头、岸台、崖体、礁石、滩涂、渔网这些主要物件会整局没有贴图，只剩底色，直到刷新页面；控制台报错，玩家自己看不出原因）

## 环境
HeadlessChrome，/usr/bin/google-chrome，带托管策略 sand-webauthn.json（ExtensionSettings 强制装扩展，BUG-008 已查明）。vite preview 构建产物，SwiftShader。每次运行都是新 profile 冷启动。脚本：/workspace/qa-tools/t7-tex3.mjs、t7-tex4.mjs。日志：/tmp/t7-tex3.log、/tmp/t7-tex4.log、/tmp/t7-tex2.log。

## 复现步骤
1. 冷启动 Chrome（不加 `--disable-extensions`），打开 `/?smoke=1&debug=1&autostart=1&art=1`。
2. 进入 S1，等到可以操作，再等 3 s。
3. 看 Network 里 ktx2 请求是否有 `net::ERR_ABORTED`，看控制台有没有 `Couldn't load texture`，再遍历 `__s1.art.root` 里各个 `mat-*` 材质有没有 `map`。

## 期望
贴图请求被取消（不管原因是扩展、网络抖动还是别的）时，像字体一样自动重试；最终所有美术材质都有贴图，控制台没有报错。

## 实际
不带 `--disable-extensions` 冷启动 6 次，5 次在导航后约 0.9–1.1 s 有一批 ktx2 被取消（net::ERR_ABORTED，canceled）。被取消的贴图没有重试，对应材质整局没有贴图：

| 运行 | 被取消的贴图 | 整局没有贴图的物件 / 材质 |
|---|---|---|
| tex3 #0 | tex-wood-ch1 ×3 | 码头 env-pier-wood-ch1、渔棚 env-fish-shed-ruin（mat-env-wood-ch1） |
| tex3 #1 | tex-wood-ch1 ×3 | 码头、渔棚、两个网架（mat-env-wood-ch1） |
| tex3 #2 | tex-wood-ch1 ×3、tex-stone-masonry ×3、tex-net-a | 码头、岸台、崖体、渔棚……（控制台 32 条错误） |
| tex3 #3 | tex-rock-shore ×3 | s1-rocks-a/b/c/d 全部 LOD（mat-env-rock-shore） |
| tex4 #0 | tex-stone-masonry ×3、tex-net-a、tex-sand-tidal… | 滩涂、岸台、渔棚、两个网架的网 |
| tex4 #1 | 无 | 无 |

对照：同样条件加 `--disable-extensions`，6 次全部 0 个被取消，0 条控制台错误，所有 mat-* 材质都有贴图。远景灯塔 `mat-sky-layer` 本来就没有贴图，两种模式都一样，没算进上表。

这和 BUG-008 是同一个取消窗口（导航后约 1 s，扩展初始化）。641e1c8 给字体留了重试，所以本轮字体一直是 attempts=1；但现在落在这个窗口里的是 KTX2 贴图，而贴图没有重试。641e1c8 的说明里提到「真实玩家的浏览器里也可能有扩展造成同样的取消，所以重试不能删」。照这个说法，贴图也需要同样的保护。

另外，batch6（a3da8e7）在同一台机器上不加参数跑了 8 个 t6-* 脚本（其中 t6-art 是 art=1），日志里控制台都是 0 错误。所以这次是 ed61faf 前后贴图请求的时间点变了，才落进了这个窗口（推测，没有逐个提交对比）。

建议（仅供参考）：KTX2 / GLB 请求遇到 TypeError 或 abort 时，按 fontLoader 的方式重试 1–2 次；或者 QA 冷启动统一加 `--disable-extensions`，但真实玩家那边仍然有风险。

## 修复说明
- **原因**：确认。GLTFLoader 加载外部 KTX2 失败时只打一条 `Couldn't load texture` 并把这张贴图当 null，GLB 本身照样成功，所以在 GLB 层加重试不够，得在贴图那一层重试。原来 AssetLoader 给 GLTFLoader 的 KTX2 共享层（按 URL 去重）只缓存 promise，失败就直接失败。GLB 本身（以及 manifest 里直接列的 ktx2）也没有重试。
- **改法**（新文件 src/assets/loadRetry.ts，规则和 fontLoader 一样）：
  - `loadWithRetry`：遇到网络层失败才重试，最多 2 次（共 3 次请求），间隔 150 / 300 ms。网络层失败指 fetch 抛 TypeError、被取消（AbortError）、HTTP 状态 0 或 5xx；404 等 4xx、解析错误和转码错误不重试。每个 URL 的请求次数、结果和是否用了占位记在 `assetStats`，可以用 `__game.assets.loadStats` 查看。
  - `createSharedKtx2`：替换原来的 KTX2 共享层，同一 URL 只有一条在飞的下载，重试也在这一条里进行，引用同一张贴图的多个 GLB 不会各发各的请求。重试用完后：打 `console.error`（带请求次数）、`<html>` 加 `assets-fallback` class、发 `assets:fallback` 事件，并返回一张棋盘格占位贴图（标 `userData.assetFallback`），不再静默变成 null。失败的不进缓存，之后再用到会重新下载。
  - GLB：`AssetLoader` 的 gltf 加载走 `loadWithRetry`，并通过 `shareInflight` 让同一 GLB URL 只下载一次。最终失败时照旧换白盒占位，另外补上 `console.error`（带已重试次数）、`assets-fallback` 和 `assets:fallback`（kind glb）。manifest 里直接列的 ktx2 也走 `loadWithRetry`。
  - 可见降级只放在颜色槽：`stripFallbackTextures` 把落在 normal / orm 等非 `map` 槽的占位贴图清掉，免得棋盘格当法线用把光照搞花；`map` 槽保留棋盘格，玩家能看出贴图缺了。
- **测试**（scripts/verify-assets.mjs，npm test 里跑，模拟取消：抛 `TypeError('Failed to fetch (net::ERR_ABORTED)')` 或 AbortError）：
  - 第一次被取消 → 重试成功（attempts 2）；一直被取消 → 共 3 次后抛出；404 和解析错误只请求 1 次。
  - 同一 URL 并发请求只下载一次。
  - 两个 GLB 同时引用同一张 KTX2 且第一次被取消 → 总共 2 次请求，两边拿到同一张贴图，没有占位；全部失败 → 棋盘格占位并调用失败回调，缓存清空，再次请求会重新下载。
  - 用真的 GLTFLoader 解析带 KHR_texture_basisu 外部 .ktx2 的 glTF（颜色和法线用同一张）：被取消后重试 → 两个槽都有贴图；全部失败 → 颜色槽是棋盘格，法线槽为空。
  - smoke「v0.1-013 S1 … ?art=1」新增：加载完成的 GLB / KTX2 全部成功，没有占位，也没有 `assets-fallback`，并列出重试过的 URL。原来的「v0.1-013 美术外部 KTX2 … 两 GLB 共享 4 张」仍然通过（共享层换了实现，去重还在）。
