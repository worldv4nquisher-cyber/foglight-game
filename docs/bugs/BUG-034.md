# BUG-034 换场第一帧平面反射在阴影贴图建好前渲染，WebGL INVALID_OPERATION（低）

- 发现：程序 M7 兼容测试。playwright WebKit（iPhone 15 模拟）跑 smoke:xb 时出现 16 条 console.error：`WebGL: INVALID_OPERATION: glDrawElements: Mismatch between texture format and sampler type (signed/unsigned/float/shadow)`。Chromium（Pixel 7 模拟）同一条只算 warning，Firefox 是「shadow sampler 绑的不是深度纹理」warning。主冒烟只收 console.error，所以一直没被抓到。
- 定位（临时插桩：每次 draw 后 getError，记 program 和纹理单元）：S2 走出口进 S3 的那一帧，在 `PlanarReflection.update`（LevelScene.beforeRender）里，gb-stone / gb-metal 等受阴影材质的 `directionalShadowMap[0]`（sampler2DShadow）绑到的不是深度纹理。原因：反射 pass 为省开销把 `renderer.shadowMap.autoUpdate` 关了；进场第一帧主画面还没跑过阴影 pass，太阳的 `shadow.map` 还是 null，three 给 sampler2DShadow 用的空深度纹理从没上传，实际绑上的是空颜色纹理。切画质改阴影尺寸（LevelScene 把 shadow.map 置 null）后的第一帧同理。
- 影响：那一帧反射贴图里受阴影的物体画不出来（换场在黑场淡入中，基本看不到）；WebKit / Safari 控制台每次换场十几条红字。
- 严重度：低
- 修法：PlanarReflection 加 `shadowLights`（LevelScene 登记太阳）；有投影灯缺 shadow.map 时，这一帧反射 pass 照常让阴影更新（建出贴图），之后仍关。修后同样插桩跑「主菜单 → 新游戏 → S1 → S2 → S3」0 处。M7 完整通关冒烟的「走出口」步骤加断言：换场期间 gl.getError 为空。
- 状态：已修（程序 M7，commit 91c4b55；完整通关冒烟加了换场 GL 错误断言），QA batch24 回归通过，已关闭

## QA 回归（batch24，2026-11-01，快照 snap-7f73706）
- 实跑：WebKit 占位（24 s）与 WebKit art=1 + XB_AUDIO_DECODE=reject（121 s）`smoke:xb` 5 步通过，0 console.error、无 INVALID_OPERATION；Firefox art=1 也没再出 shadow sampler 警告；M7 完整通关 takeExit（S1→S2、S2→S3）GL 错误断言通过
- 覆盖缺口（低）：GL 断言只在 takeExit；继续 / 刷新进场、S3→章末、新游戏进场后没查；断言在 Chrome swiftshader 下的灵敏度没做反向验证
