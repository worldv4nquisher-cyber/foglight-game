# BUG-019 裁定 19 西窗外限高带：走进带内时相机一帧从 6 m 收到 0.87 m（瞬跳 ≈5.1 m）

- **关联**：7cbf018（S2 西窗外室外第三人称相机限高带）。
- **发现**：QA batch12，2026-10-30 16:5x（UTC+7），snap-a3a2a04。
- **严重度**：中低（不影响 317 谜题判定，sample-317 B=0 仍成立；但走近西窗外时镜头明显"啪"地贴到背后，正是这次要验的"窗口附近相机不跳"）。

## 复现步骤
1. `?scene=s2&art=1&smoke=1&debug=1`，出西门到西窗外坡地，相机距离滚到最大 6 m、俯仰压到最低（-35°，相机最高）。
2. 站在视线带远端外侧（玩家 x ≈ 11.3，z ≈ 0.9，相机在玩家 +x 侧朝房子看），按 W 朝房子走。
3. 或：在带中段（x ≈ 6.4）带外侧 z ≈ 6，相机在玩家身后（+z 侧），朝 −z 横着走进带内。

## 实际
- 浏览器（t12-cam19，帧记录 docs/bugs/qa-v0.1-batch12/cam19/b12-cam19-KeyW.json 第 7→8 帧）：玩家停在 x 10.496 没动，相机位置一次更新从 (15.44, 4.61) 跳到 (11.21, 1.67)，距离 6.00 → 0.872，`heightCapped` false → true。
- 60 Hz 固定步复算（同一函数 `cameraHeightCapDistance` + `s2CameraHeightCaps`，不含物理碰撞；qa-v0.1-batch12/cam19/t12-cam19sim.mjs）：
  - 沿视线走向房子，走路 1.6 m/s / 跑 3.2 m/s：在 s ≈ 9.5（玩家 x ≈ 10.0）处**单帧**距离 6 → 0.87，相机位移 5.15 / 5.17 m。
  - 从 +z 侧正面走进带（相机在身后 +z）：同样单帧 6 → 0.87（5.15 m）。
  - 反方向（出带）是 0.25 s 平滑恢复，单帧 ≤ 0.55 m，正常；相机在 +x 侧、玩家侧移进带时单帧 ≤ 0.72 m（走）/ 1.39 m（跑），可以接受。
- 原因推测：限高低于"支点 + 0.5 m"下限时，`cameraHeightCapDistance` 直接返回射线碰到下限的距离（俯仰 -35° 时 ≈ 0.87 m）；限高在下限上方一点点时整条射线都不碰 → 返回 6 m。两种情况之间没有过渡，玩家挪 2–3 cm 就从 6 m 跳到 0.87 m；再加上"被挡立即前拉"不做平滑，于是一帧跳完。
- verify-camera 的断言只检查限高值沿 z 的连续性（< 0.5 m），没有检查相机**距离 / 位置**的逐帧连续性，所以 npm test 通过。

## 期望
走进带内时相机平滑收近（像出带的 0.25 s 恢复那样），或者限高本身在下限附近有过渡；单帧位移不应达到米级（commit 说明里写的是"不跳"）。
