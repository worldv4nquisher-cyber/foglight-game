# BUG-002 检测中途被玩家手动改档（aborted）或检测前已手动选档（skipped）后，暂停菜单底栏显示「自动检测：极致」，实际没有检测结果

- 关联：v0.1-009 / c73645f（PauseMenu.refresh 底栏、QualityManager.detected、QualityBenchmark.abort/start）
- 严重度：轻微（文案误导，不影响画质本身）
- 测试版本：c73645f 快照 /workspace/qa-tools/snap-c73645f/game

## 复现步骤
1. `localStorage.clear()`，打开 `/?simulateFps=40` 进入主场景。
2. 自动检测进行中（极致档测完、降到「高」后），按 Esc 打开暂停菜单，点画质「极致」（或任意档）。
3. 继续游戏，再按 Esc 看暂停菜单底栏。也可以把画质切到「标准」后再看。
4. 另一条路径：检测前就手动选过档（设置为 qualitySource=user），进 S1 时检测被跳过（skipped），start() 同样只写 qualityDetected=true。实测 state=skipped、detected=true；按代码，底栏也会显示「自动检测：<qualityDetectedTier>」，这一条底栏文字没有单独截图，属于代码推断。

## 期望
检测没有完成，底栏应显示「尚未自动检测」，或者另给一句「已手动选择」之类的文案，不应声称自动检测得出了某一档。

## 实际
- benchmark.state = aborted，设置里 qualityDetected=true，qualityDetectedTier 仍是默认值 ultra。
- `QualityManager.detected` 只看 qualityDetected，因此返回 'ultra'，底栏显示「自动检测：极致 · GPU：… · Esc 继续」。截图里当前档位是「标准」，底栏仍写「自动检测：极致」。
- 连带影响：之后点「恢复默认」会以「自动检测结果」的名义回到极致（source=auto），而极致从没测过。
- abort 本身工作正常：立即停止，以玩家选择为准，刷新后不再检测。

## 修复说明

- 修复提交：game/ 仓库 `2d717a1`（单独一个提交，只含 BUG-002 相关改动）；后续 008 `95fc1da` 把状态行移到共用设置界面，规则不变。
- 根因：检测被打断（aborted）/ 跳过（skipped）时只写了 `qualityDetected=true`，`qualityDetectedTier` 保留默认值 `ultra`，`QualityManager.detected` 只看 `qualityDetected`，于是把「极致」当成检测结果。
- 改动：
  1. `qualityDetectedTier` 改为 `QualityTier | null`，默认 null；**只有检测完成（done）才写入**。aborted / skipped 显式写 null；读设置时 `qualityDetected` 不为 true 或值非法一律清成 null（老存档里残留的 `ultra` 也会被清掉）。
  2. `detected` 为 null 时，暂停菜单（008 起为共用设置界面的画质状态行）显示「尚未自动检测」（文本 `ui.settings.quality_undetected`）。
  3. 「恢复默认」：有检测结果 → 回到检测结果（来源 auto）；没有结果（未检测 / 打断 / 跳过）→ 回到默认极致（来源 default）。
  4. 检测没完成就离开 S1（如 008 的「回到主菜单」）：`QualityBenchmark.cancel()` 整次作废，什么都不写，运行时档位退回设置档位，下次进 S1 重测。
  5. 时机按 009 裁定：第一轮落在建立镜头内（建立镜头播完停在最后一帧等第一轮测完，最多多停 5 s）；降档后的复测在玩家可移动后继续。切档的画布重建（setPixelRatio / setSize 会清空绘图缓冲）推迟到下一帧渲染之前执行，检测更新也挪到渲染之前，避免可见黑帧。035 开场演出接入时检测放进演出最后 9 s。
  6. 规则不变：只首次启动检测、< 50 fps 降档后复测、最多降两档、手动选择随时生效且可改回。
- 回归：`npm run test:quality` 新增「打断 / 跳过不写结果、显示尚未自动检测、恢复默认回极致」「cancel 作废重测」「firstRoundDone」；`test:camera` 新增 holdUntil；`npm run smoke` 的 009 项新增：本文复现步骤原样操作（检测中暂停菜单改「标准」→ 底栏「尚未自动检测」、恢复默认 → 极致 / default / tier=null）、第一轮降档发生在建立镜头内且第二轮在交还之后、`debugStats.resizeAfterRender === 0`。
- 遗留：切档黑帧 < 1 s 与 50 fps 分界需真实 GPU 上确认（本机无 GPU，按约定不做帧率实测）。

## 回归结论（QA batch3，2026-10-29，快照 95fc1da preview，headless Chrome SwiftShader）
- 回归结论：**通过，关闭。**
- 测试环境：preview 需要加 ?smoke=1 才能拿到 __game。
- `localStorage.clear()` 后打开 `/?simulateFps=40&autostart=1&debug=1&smoke=1`：
  - 切档顺序：ultra→high（auto，发生时镜头为 cutscene，即建立镜头内），high→standard（auto，镜头已交还 explore）。
  - 最终设置：qualityDetected=true，qualityDetectedTier=standard。
  - 设置界面状态行显示「自动检测：标准」。「恢复默认」后为 standard / auto，状态行不变。
- F3 面板（debug=1 下默认隐藏，按 F3 打开）检测过程中显示进度：
  - 「自动检测中：高 x s · 已测 ultra n」
  - 「自动检测中：标准 x s · 已测 ultra n / high n」
  - 检测完成后显示「画质 标准（自动）」。
- 检测中改档（打断）：在暂停 → 设置里点「标准」后：
  - state=aborted，qualityDetectedTier=null，状态行显示「尚未自动检测」。
  - 再点「恢复默认」：变为 ultra / default，灵敏度 1，状态行仍为「尚未自动检测」。
- 进 S1 前先在主菜单设置里选「高」（跳过检测）：state=skipped，qualityDetectedTier=null，状态行显示「尚未自动检测」。
- 检测没完成就离开 S1：回到主菜单后 state=idle，qualityDetected=false，detectedTier=null，quality=ultra，检测整次作废。
