# BUG-035 手机浏览器能进游戏但无法操作，也没有「仅支持桌面」提示（中）

- 发现：程序 M7 兼容测试。playwright 手机模拟跑 smoke:xb：WebKit「iPhone 15」、Chromium「Pixel 7」都能从主菜单进 S1→S2→S3、无报错，但画面底部显示的是桌面键位提示（W A S D 移动 / Shift 小跑 / 点击画面锁定视角 / E 互动 / 右键观察 / 滚轮远近 / Esc 暂停），没有任何触屏控件（`.touch-controls` 不存在），也没有「请用电脑打开」之类提示。
- 原因：按 v0.1.md「2026-10-29 用户决定：不考虑手机玩家，仅桌面浏览器」，Game.ts 只注册键鼠输入，TouchInput 保留代码但不注册（属设计如此）。缺的是提示：`device.isTouch` / `device.isMobile` 已能判断，但启动流程里没有据此给出说明。
- 影响：手机用户能看到画面、点「新游戏」进场，但走不了路也无法交互，只能看到用不上的键盘提示。不满足 M7 兼容范围「手机只要求能打开，并给出正确提示或能运行」。
- 严重度：中（桌面不受影响）
- 修法（原建议，已按下方实现）：启动时判定手机 / 无精确指针设备，主菜单给出「仅支持电脑」提示；文案 ID `ui.notice.desktop_only`（策划 2026-11-01 交付，4ae9fcf）。
- 附带观察（模拟器限制，不算 bug）：iPhone 模拟 fullscreen / pointerLock API 不存在（代码已有 supportsPointerLock 兜底）；AudioContext 一直是 `interrupted`（桌面 WebKit 无头也一样，是无头 WPE 没有音频输出，需真机确认）。早先一次 iPhone 跑出的空 `pageerror:` 在 BUG-033/034 修复后重跑未再出现（smoke:xb 已改为打印 name/String(e)，再出现能看到内容）。
- 修复（程序，2026-11-01，eda3534）：
  - 判定：纯函数 `src/platform/desktopOnly.ts` `isDesktopOnlyBlocked`，`device.desktopOnlyBlocked` 启动时算一次。顺序：① 有任何能悬停的精确指针（`(any-pointer: fine)` 且 `(any-hover: hover)`，即鼠标 / 触控板）→ 放行，所以触屏笔记本、Windows 平板模式、iPad 接妙控键盘都不拦；② 主指针 `(pointer: coarse)` 且不能 `(hover: hover)` → 提示；③ 浏览器不支持 pointer 媒体查询时，移动系统 / Mobi UA + 有触摸 → 提示。其余放行。verify-input 加 9 种设备组合单测。
  - 表现：按 text-ch1.md 的触发条件「替代主菜单显示」——主菜单首页保留标题（logo），按钮隐藏，下方居中显示 `t('ui.notice.desktop_only')`；宋体正文字号、宽行距、次要文字色，上方一截 48 px 细琥珀渐变线（呼应远处的灯）；竖屏下标题 / logo 按视口缩放，不横向溢出。背景仍是主菜单实时场景 + 音乐。存档提示（`ui.save.*`）在这种设备上不显示。`?autostart=1` / `?scene=`（测试参数）不受影响。
  - 冒烟：主冒烟新增「v0.1-BUG-035 仅支持电脑提示」（桌面 / 触屏笔记本模拟不出提示，CDP 手机模拟出提示、文字与文本表一致、按钮隐藏、在视口内）；smoke:xb 手机模拟（iPhone 15 / Pixel 7）改为断言提示后结束，桌面断言不出提示。
- 状态：已修（程序，eda3534 + 冒烟 4008aed），QA batch24 回归通过，已关闭；真机确认见 docs/releases/v0.1-compat-report.md §7「手机 / 平板 / 触屏笔记本：BUG-035」：
  - M1 iPhone Safari → 拦
  - M2 Android Chrome → 拦
  - M3a iPad 纯触屏 → 拦
  - M3b iPad 接妙控键盘 / 鼠标 → 放行（预期、待真机确认）
  - M4a 触屏 Windows 笔记本（键盘、触控板在） → 放行
  - M4b Windows 平板模式取下键盘 → 拦（预期、待真机确认）
  - 每项的依据（pointer / any-pointer / any-hover 的典型值）和确认步骤（竖屏 / 横屏、提示在视口内、字体）都在报告里
