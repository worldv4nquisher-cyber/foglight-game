# BUG-009 操作提示折成两行时，「日志已更新」和它重叠

- **关联单号/commit**：BUG-004 的修复（1cd47ae，`.toast-left` 改到 `bottom: 48px`）。011 / 012 往测试场地的操作提示里加了潮汐、光路的说明，提示变长后就露出了这个问题。在 master 4f672e9 快照上复现。代码位置：src/ui/styles.css:590-602（`.toast-left`），:174（`.hud-hint`）。
- **发现**：QA batch5，2026-10-29 20:2x（UTC+7）。smoke 的 005 项也因为这个失败（「『日志已更新』和操作提示重叠 / 被盖住」）。
- **严重度**：轻微。目前只在测试场地出现（DEV_ONLY）。正式关卡 S1 的提示只有一行（宽 599 px），在 1280×720 和 960×540 下都不重叠。但 `.toast-left` 的位置是按「提示单行约 22 px」写死的，以后正式关卡的提示一变长，或者窗口窄到提示折行，就会重叠。最后这一点是根据 CSS 推断的，窄窗口没有实测。

## 环境
HeadlessChrome/156，Linux，vite preview 构建产物，SwiftShader。脚本：/workspace/qa-tools/p5-misc.mjs 和 p5-lh.mjs，日志 /tmp/p5-misc.log、/tmp/p5-lh.log。

## 复现步骤
1. 打开 `/?smoke=1&debug=1&scene=testbed`，窗口 1280×720，进入 explore。
2. 触发一次「日志已更新」：在测试场地第一次读告示即可。探针里直接用的是 `__game.events.emit('journal:updated', …)`。
3. 看左下角：「日志已更新」和操作提示的位置关系。

## 期望
「日志已更新」完整显示在操作提示上方，和提示不重叠（这是 BUG-004 的验收）。

## 实际
测试场地的操作提示折成两行，高 43 px；单行时是 22 px。toast 还在固定的 bottom 48px，压在提示第一行上：

| 场景 | 窗口 | toast [左,上,右,下] | 提示 [左,上,右,下] | 提示行数 | 重叠 |
|---|---|---|---|---|---|
| testbed | 1280×720 | [16,653,81,672] | [16,663,1280,706] | 2 | **是** |
| testbed | 960×540 | [16,473,81,492] | [16,483,960,526] | 2 | **是** |
| S1 | 1280×720 | [16,653,81,672] | [16,684,615,706] | 1 | 否 |
| S1 | 960×540 | [16,473,81,492] | [16,504,615,526] | 1 | 否 |

smoke 里测到的值和上表一致：toast [16,566,81,585]，hint [16,576,1280,619]。

建议（仅供参考）：把 toast 放进和提示同一个自下而上排的容器里，或者按 `.hud-hint` 的实际高度来定位，不要写死 48px。

## 修复说明
- 修复提交：game/ 仓库 `620a14d`（单独一个提交，只含 BUG-009 相关改动）。
- 根因：`.toast-left` 的位置写死成 `bottom: 48px`，是按一行操作提示的高度算的。testbed 里提示折成两行（高约 43 px）后，提示条往上长，就盖住了 toast。
- 改动：
  1. `src/ui/Hud.ts`：新增 `syncHintHeight()`，把操作提示 `.hud-hint` 的实际高度写进 UI 根节点的 CSS 变量 `--hud-hint-h`（HUD 隐藏时写 0）。show / hide / setHint 时调用一次，另外用 ResizeObserver 跟踪窗口缩放和换行。dispose 时断开 observer、删掉这个变量。
  2. `src/ui/styles.css`：改成 `.toast-left { bottom: calc(14px + var(--hud-hint-h, 22px) + 12px) }`，也就是提示的底边距 + 提示实际高度 + 12 px 间距。提示有几行，toast 就往上让几行。
- 回归：smoke 005 原有一项检查「关掉后显示『日志已更新』、不压操作提示」。这次在它后面又加了一步：临时把提示换成三行，断言 toast 和提示不重叠，然后恢复原提示。`npm run build` 和 `SMOKE_ONLY='005' npm run smoke` 都通过，tsc、eslint 也干净。
- 遗留：无。如果以后左下角还要加别的浮层，也应该用 `--hud-hint-h` 来定位。

## 回归（QA batch7，2026-10-29 23:35 UTC+7，ed61faf 快照）
- 状态：**关闭**。testbed 和 s1 在 1280×720、960×540、600×400 下都测了：toast 不和 `.hud-hint` 重叠，也都在画面内，间隙 12 px；提示变成 2–3 行时 toast 会跟着上移。
