# BUG-037 机关转镜 / 走路的方向键「轻点」比一帧短时被吞（中）

- 发现：程序 batch27 ③ 重写 S3 导光镜冒烟（去掉补按重试、每次只按一下、精确断言）时，第一下 D 轻点（CDP rawKeyDown + keyUp 连发）后镜子不动；页面 keydown 计数 = 1（浏览器确实送到了），游戏角度 [0,0] 不变。batch26 的冒烟是「按住直到转了再松」+ E / R / Tab 各重试 3 次，把这个问题盖住了。
- 原因：`InputManager.getAxis` 只按帧采样「此刻是否按住」（rawHeld）。按下和松开都落在两帧之间时，下一帧采样已经松开 → 轴向 0 → `PuzzleMode.keyStep` 看不到这次按键。按钮类动作（E / R / Tab / Esc）走 `markPressed` 缓冲，不受影响；只有 moveX / moveY 轴向（机关 A/D、W/S 转动，探索走路）会丢。
- 影响：帧率越低越容易丢——无头 SwiftShader 几 fps 时几乎每下轻点都丢；真机 60 fps 时一帧 16 ms，人手轻点一般 50 ms 以上，很少遇到；但低端机 / 软件渲染（20 fps 以下）快速轻点转镜会「按了没反应」，玩家会以为按键失灵。
- 严重度：中（影响解谜操作手感，低帧率下可感知；不卡流程，按住仍能转）
- 修法：`InputManager` 新增 `tappedThisFrame`（上次 endFrame 后按下过的键码）。`getAxis` 把「本帧按下过」也算按住一帧；`endFrame`、切上下文、`enabled=false`、`releaseAll`（失焦）都清掉。按住的行为不变；松开不算新的按下。只作用于轴向，不改 `isDown`（Shift 精调 / 冲刺 / 右键观察仍按真实按住判断）。
- 验证：test:input 新增 2 条（同帧轻点读到一次 ±1、下一帧回 0、按住不变；上下文切换 / 失焦 / 关闭输入不残留）；冒烟「v0.1-batch27-S3 导光镜真实键鼠」每一下都是真实轻点、不重试、精确角度。

## QA 回归（batch27，2026-11-01 14:35–14:38 UTC+7，snap-7097d7f 测试构建，无头 SwiftShader 约 0.3 fps）—— 通过
- 机关（S3 窗口镜）：同帧合成轻点 D A A D W S 每下精确 1 档（含 345° 回绕）；CDP 真实轻点 ×12 都是同帧，12/12 每下 1 档；模拟修复前的对照组被吞（[0,0]）。
- 探索：同帧轻点 W 走一帧（0.08519，等于按住一帧的距离）；对照组走 0。
- 按住 D 约 2.5 s：先转 1 档再连发，松开即停，按住行为不变；Shift 同帧轻点后 isDown 仍为 false。
- test:input 16/16 ✓。
