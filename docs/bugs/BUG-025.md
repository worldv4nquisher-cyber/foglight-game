# BUG-025 章节结束页 → 主菜单：菜单曲直接满音量起播，没有淡入

- 版本：1d5405b（r3 dist，snap-1d5405b），art=1，headless Chrome + SwiftShader
- 严重度：P3（音频听感：硬切入；无报错、不影响流程）
- 状态：closed（2026-10-31，QA batch18 ① 回归通过，fe19ab7 / snap-fe19ab7；修复 366fbd4 + a8cdf05）
- 发现于：QA batch17 ⑤

## 复现
1. `?debug=1&art=1&scene=s3`，点一下解锁音频，等能操作。
2. `__s3.lightTheLamp()`，然后按住 Space 1 s 跳过（或者等结尾曲放完，约 106 s）→ 章节结束页。
3. 点「回到主菜单」。

## 期望
主菜单曲 mus-menu 淡入（brief ⑤；035 进度记录写的是「结束页 → 主菜单的菜单曲淡入不动」，即按原有淡入处理）。

## 实际
- musicLog：`{op:'play', key:'mus-menu', from:null, fade:0, loop:true}`；回菜单后第一次采样（约 0.2 s）曲目 gain 就已经 = 1.035（=gainDb 0.3 的满值），之后 3 s 一直不变（qa-v0.1-batch17/skip/t17-skip-end.json `menu` / `menuLog`）。
- 原因（读代码）：MenuScene.startMusic → `switchMusic(..., MENU_MUSIC)` 只传 `crossfade`；AudioSystem.playMusic 里 `fade = prev ? crossfade : (opts.fadeIn ?? 0)`。结束页时结尾曲已经放完（end）或被跳过停掉（stop 0.75），没有 prev → fade=0，直接满音量。从场景暂停菜单回主菜单时有 prev，2 s 交叉淡化正常。switchMusicLazy 在「上一首已停」时会传 fadeIn，同步的 switchMusic 没传。
- 建议：switchMusic 在 buf 存在、当前没曲时传 `fadeIn: crossfade`（与懒加载路径一致）。
