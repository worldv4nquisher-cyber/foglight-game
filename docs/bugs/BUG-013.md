## 修复说明（程序，2026-10-30 UTC+7）
- **结论：大部分差距来自测量口径，不是游戏速度。** 楼梯是离散台阶，y 随时间是阶梯函数。QA 脚本取「窗口内第一个采样点 → 最后一个采样点」算 Δy/Δt。首点刚迈上某一级，末点在最后一级平台的末尾，所以分母多出将近一整段平台，n 级会低约 1/(n+1)；采样稀疏时还有 ±1 级的抖动。
  - 复核：在 node 里按控制器同样的走法（StairGait → stepLocomotion → 物理）走 S2 直梯，同一条轨迹逐 tick 采样。端点法得 0.498；每 4–16 tick 采样一次得 0.502–0.541，与 QA 的 0.505–0.518 吻合。按「迈级到迈级」口径算同一条轨迹是 0.5435（−0.4%）。
- **另外修了一个真实的小问题：从平台或小跑进楼梯的过渡段。** StairGait 的坡度原来用指数平均 (旧 + 新)/2。进楼梯时量到的第一级偏陡（例如按住 Shift 从小跑减速时量得 0.88，实际 0.768），要 4–5 级才收敛到 ±1%，Shift 上下 S2 直梯中段只有 0.536–0.539（−1.2 至 −1.8%）。现在改为最近两级的平均，第 3 级起就收敛（`src/systems/locomotion.ts`）。
- **测量口径（verify-physics 写明）：** 竖直速度 = (最后一次迈级时的 y − 第一次迈级时的 y) / 两次迈级之间的时间。只算纯楼梯段：直梯首尾各去掉 3 级（平台 ↔ 楼梯过渡）；螺旋梯取 1.5 s 之后、到顶之前的部分。
- **修后实测（迈级到迈级，±1% 断言）：**
  - S2 直梯：上 0.5422、上 Shift 0.5455、下 0.5422、下 Shift 0.5422 m/s。
  - testbed 螺旋梯：上 0.5437、上 Shift 0.5455、下 0.5414 m/s。
  - 以上全部在 0.5455 ±1% 内。verify-physics 新增「BUG-013 S2 直梯」用例，螺旋梯用例的容差从 ±0.03 收紧到 ±1%。
- **QA 复测建议：** 用迈级到迈级口径，即记录 |Δy| > 0.08 的那些 tick，取首尾两次迈级算。不要用窗口端点。
