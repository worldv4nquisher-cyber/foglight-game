- **关联**：v0.1-015 谜题 5（E 点灯）。代码位置：src/systems/interaction/InteractionSystem.ts pickCandidate。
- **发现**：QA batch8，2026-10-30 01:xx（UTC+7），4eb6562 快照，art=0 和 art=1 都能复现。358a1a1 复测仍然存在（2026-10-30 03:4x UTC+7）。
- **严重度**：一般（流程不会卡死，镜头偏开就能点；但可点灯是 E 时机判定的关键时刻，玩家按 E 却打开透镜说明，只有 0.3 s 宽限的那一下也会被吃掉）。

## 复现步骤
1. ?scene=s3，开油阀，三面镜子转到位，受光 1.0 s 进入 ready（可点灯）。
2. 站到拉杆交互点 ignite-lever-s3-interact (1.45, 22, −0.15)，面向拉杆，相机在身后，pitch −0.2。
3. 看提示，然后按 E。

## 实际
- 提示是「E 查看」，current = lens-s3。按 E 打开透镜说明（interact:used lens-s3），不点灯。
- 在这个站位把 yaw 扫 ±0.6 rad、pitch 扫 0 / −0.25 / −0.5，共 21 个方向：16 个选中透镜，只有 5 个是拉杆（镜头往左偏 0.4–0.6 rad 才出现）。正前方三档全是透镜。

## 期望
可点灯期间，拉杆只要在交互范围内就优先，提示「E 点灯」。也可以在 ready / 宽限期间关掉透镜的 inspect。

## 原因（读码）
- pickCandidate 按焦点投影离屏幕中心的距离选。
- 358a1a1 新加的 aimCone 规则只对带 aimCone 的候选生效。lens-s3 没有 aimCone，拉杆 priority 20 也压不过它。
- 从拉杆站位看，透镜焦点（灯室中心 y≈22.85）和拉杆握把几乎在同一个方向。

## 修复说明（commit b244f2e，2026-10-30 UTC+7）
- **原因**：确认。拉杆站位看过去，透镜焦点（灯室中心 y 22.85，reach 0.6）和拉杆握把几乎在同一个方向；pickCandidate 按离屏幕中心距离选，priority 只和跨越点比，透镜（0）压不过也让不开拉杆（20）。358a1a1 的 aimCone 只对设了 aimCone 的候选生效，透镜没设。
- **改法**：可点灯时暂停透镜查看（没用 aimCone）。src/levels/s3/puzzles.ts 把透镜 inspect 存为 `lensIx`，每个固定步 `lensIx.enabled = !leverIx.enabled`。拉杆开放 = canIgnite()（开阀 + 点火口 ready + 未在点灯 / 未点燃），0.3 s 断光宽限内 ready 不掉，所以宽限期间也是「E 点灯」唯一。两者在同一步切换，不会有两者都可选的帧。不可点灯时（没开阀、光没到、断光超时退出、点燃后）透镜照常「E 查看」。
  - 没用 aimCone 的原因：aimCone 只让「没对准」的低优先级候选让位；正前方几档透镜焦点离屏幕中心本来就近，对准时仍会压过拉杆，要靠调半径碰运气；暂停是确定性的。
- **测试**：
  - verify-interaction 新增「BUG-015 S3 灯室」：用 S3 layout 真实坐标（拉杆交互点 / 握把 / 透镜 socket）+ gameplay.camera 探索相机参数，站在拉杆交互点面向拉杆，相机 yaw ±0.6（0.2 一档）× pitch 0 / −0.25 / −0.5 共 21 个视角：
    - 改前（两者都开放）复现 QA 的拉杆 5 / 透镜 16；
    - 可点灯（lens.enabled = !lever.enabled）21/21 选拉杆，提示「E 点灯」；
    - 不可点灯时透镜仍是候选；并断言场景代码里有 `lensIx.enabled = !leverIx.enabled`。
  - smoke「v0.1-015 S3 谜题 5 流程」（art=0，SMOKE_ONLY 单跑通过）：可点灯时 lensIx.enabled 为 false；在拉杆 standPoint 面向拉杆，cameraFollow yaw = 面向 + π + (−0.6..0.6) × pitch 0 / −0.25 / −0.5 共 21 个视角，每个视角等 3 个固定步，全部 current = ignite-lever-s3，提示「E 点灯」；之后原有的按 E 点灯 / 独白 / 结束页流程照常通过。
