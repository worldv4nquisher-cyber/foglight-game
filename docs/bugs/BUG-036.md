# BUG-036 软件渲染提示文案的「顿」不在字体子集里（低）

- 发现：程序 batch26 收尾跑 test:fonts：「✗ 字体子集缺 1 个字：顿」。cd5e7d5 加的 `ui.notice.software_render`（「……画面可能会卡顿。……」）是第一个用到「顿」的文本，加文案时没重新跑 `npm run fonts`。
- 影响：主菜单软件渲染提示里的「顿」会退到系统字体（字形 / 粗细和前后字不一样）；check:release 的 test:fonts 会失败。
- 严重度：低
- 修法：`npm run fonts` 重新生成子集（+顿；「孤忧郁」只出现在注释里，去掉），711 字，foglight-sans 223 KB / foglight-serif 312 KB。策划文案没动。
- 状态：**已关闭**（QA batch26 回归通过，2026-11-01 11:45 UTC+7，snap-32455f3）

## QA 回归（batch26，snap-32455f3，2026-11-01 11:38–11:45 UTC+7）

- test:fonts ✓：711 字，子集 711 字。
- foglight-sans 和 foglight-serif 的 cmap 都含「顿」U+987F（fontTools 读 woff2）。
- zh-CN.ts 179 条、537 个不同字符全量比对：两份字体子集都只缺 `\n`（换行，不是字形）。
- 生产 preview（SwiftShader）主菜单的软件渲染提示：CDP `CSS.getPlatformFontsForNode` 显示 45 个字形全部来自网页字体 `NotoSansCJKsc-Regular`（foglight-sans 子集的内部名），`isCustomFont: true`，没有退到系统字体。截图 qa-v0.1-batch26/shots/b26-software-notice-menu.png。
- 结论：关闭。
