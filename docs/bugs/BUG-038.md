# BUG-038 桌面浏览器拒绝指针锁定时不会回退鼠标拖拽，只能用键盘转镜（中）

- 发现：QA batch27（2026-11-01），代码 7097d7f。先读代码定位，再在浏览器复现。
- 严重度：**中**。只要在不给指针锁定权限的环境里打开游戏，鼠标转视角和机关鼠标转镜就完全失效，只剩键盘能用。常见环境：
  - 嵌入页面的 iframe 没有 `allow-pointer-lock`（itch.io / 门户站常见）；
  - 浏览器策略或扩展拒绝锁定；
  - Esc 解锁后冷却期内点击。

  这时 S3 窗口镜仍能用 A/D、W/S 解，不会卡死流程。但探索时完全不能用鼠标环顾，玩家会以为鼠标坏了，而且没有任何提示。
- 环境：Chrome（box 上的无头 Chrome，SwiftShader），测试构建 snap-7097d7f，`?smoke=1&art=0&debug=1&scene=s3`，1280×720。

## 复现步骤
**方法 A（iframe 没给权限）**：
1. 在同源页面里放 `<iframe sandbox="allow-scripts allow-same-origin" src="…/index.html?…&scene=s3">`，不给 `allow-pointer-lock`。
2. 等进入 S3 后，在 iframe 里点画面。
3. 按住左键向右拖 200 px。
4. 走到窗口镜前按 E 进机关，再按住左键向右、向上拖。
5. 按一下 D。

**方法 B（模拟锁定报错）**：在顶层页面加载前，把 `Element.prototype.requestPointerLock` 换成「派发 `pointerlockerror` 并返回被拒的 Promise（DOMException）」，然后照方法 A 的第 2–5 步做。

## 实际（两种方法结果相同）
- 点画面后没有锁定（`pointerLockElement` 为 null），document 收到 `pointerlockerror`。
- 探索时拖 200 px：look 增量调用 **0 次**，视角不动。
- 机关里拖动：角度一直是 [0,0]，look 增量 0 次。每点一下都只是再请求一次锁定，又收到一次 `pointerlockerror`（拖 4 次 → 4 次 pointerlockerror）。
- 按 D：转到 [15,0]，键盘正常。

## 期望
锁定被拒或报错时（同步抛错、Promise 被拒、`pointerlockerror`），自动回退到「按住左键拖拽转视角」模式，探索视角和机关转镜都能用鼠标操作。环境允许锁定后，可以再锁回去。

## 原因（src/systems/input/KeyboardMouseInput.ts @7097d7f）
- 拖拽模式只在 `!this.lockWanted` 时启用。`lockWanted = gameConfig.input.pointerLock && device.supportsPointerLock && !device.isTouch` 只看浏览器支不支持锁定，不看锁定请求有没有成功。
- 没有监听 `pointerlockerror`。`requestPointerLock` 里 Promise 被拒的结果被 `r.catch(() => undefined)` 吞掉；catch 块注释写着「回退拖拽模式」，但实际什么也没做。
- 所以锁定被拒时：
  - 每次点画面都只是重新请求锁定，然后 return；
  - pointermove 因为 `!isLocked && !dragging` 被忽略。
- 类注释写的是「不支持指针锁定（或被拒绝）时回退：按住鼠标左键拖拽转视角」，与被拒时的实际行为不符。compat-report §7 S3 也写了「桌面浏览器拒绝指针锁定时不会回退拖拽」。

## 程序修复说明（程序追加，2026-11-01）
- **修复 18cc26f**（基线 7097d7f，src/systems/input/KeyboardMouseInput.ts）：
  - 拆开「支持锁定」（原 lockWanted）和「被拒」两件事：新增 `lockDenied`，拖拽模式改为 `dragFallback = !lockWanted || lockDenied`。
  - `requestPointerLock(fromClick)`：点击画面发起的请求，被拒的三种形式都接住——同步抛错（catch）、Promise reject（`.catch`）、`pointerlockerror`（新增 document 监听，靠 `pendingClickLock` 归属到最近一次点击请求，dispose 时解绑）→ 置 `lockDenied`。
  - 被拒那一下左键还按着（`lockClickHeld`）且在 locked 上下文：立即 `dragging = true`，不用松开再按。
  - 拖拽模式下点击照常当游戏输入（不再「只锁定、return」）；距上次被拒超过 `LOCK_RETRY_MS`（1.5 s）的点击顺带再试一次锁定。
  - `pointerlockchange` 锁上时清 `lockDenied` / `dragging`，回到锁定模式。
  - 切回 locked 上下文时的自动重锁（无用户手势，被拒属正常）不算被拒，不进拖拽。
  - 能锁定时行为不变（锁定那一下点击仍只用来锁定，机关 / 阅读右键退出照常透传）。
  - 改正错误注释：文件头「不支持指针锁定（或被拒绝）时回退」、catch 里「回退拖拽模式」（原来并未实现）。
- **单测**：scripts/verify-pointer-lock.mjs（桩 DOM，`npm run test:pointerlock`，已接入 `npm test`）9 项——三种被拒各自能拖（含被拒那下按住直接拖、松开不转、再按住还能拖、点击不再被吞）、机关上下文 look 增量、1.5 s 重试后锁回退出回退、正常锁定不变、请求未决时不进拖拽、自动重锁被拒不进拖拽、dispose 解绑。旧代码 0/9、新代码 9/9。verify-interaction 里匹配源码写法的断言同步。
