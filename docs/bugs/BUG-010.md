# BUG-010 浮台没离开原位，涨潮时也说「它漂回去了。」，而且每次涨潮都会再说

- **关联单号/commit**：v0.1-013（S1 白盒 + 谜题 2），game commit a3da8e7。代码位置：src/systems/tide/Floatable.ts:92-99（不在锚位、刚浮起就进入 `drifting`，没有判断是否离开了原位）；src/levels/s1/puzzles.ts:265-268（`drifting` 结束就 `say('ch1.s1.raft.drift_back')`，没有「只第一次」的限制）。
- **发现**：QA batch6，2026-10-29 21:0x（UTC+7）。
- **严重度**：轻微。不影响通关，但旁白和画面对不上：浮台根本没动，汐却说「它漂回去了」。正常玩家很容易碰到：先敲钟退潮，没推浮台又敲钟涨潮。

HeadlessChrome，Linux，vite preview 构建产物（snap-a3da8e7），SwiftShader。脚本 /workspace/qa-tools/t6-p2b.mjs（第一项）、t6-p2.mjs，日志 /tmp/t6-p2b.log、/tmp/t6-p2.log。

## 复现步骤
1. 新开 `/?smoke=1&debug=1&autostart=1`，进入 S1（开局是涨潮）。
2. 走到潮汐钟前按 E，退潮。浮台搁浅在原位 (9.1, 0.4, 10.5)。
3. 不碰浮台，再按 E 敲钟涨潮。
4. 等浮台浮起，看字幕。
5. （可选）再退潮、再涨潮，看字幕。

## 修复说明
- 修复提交：game/ 仓库 `86b8f25`（单独一个提交，只包含 BUG-010 的改动）。
- 根因：
  1. `Floatable.fixedUpdate` 判定「刚离地」时，只要不在锚位就进入 `drifting`，没有检查浮台有没有离开原位。所以浮台停在原位时涨潮，也会走一遍漂回演出（虽然是从原位漂到原位）。
  2. `puzzles.ts` 的 float:state 监听在 `drifting` 结束时每次都调用 `say('ch1.s1.raft.drift_back')`，没有「只第一次」的限制。
- 改动：
  1. `src/systems/tide/Floatable.ts`：不在锚位时，如果水平离原位 < 5 cm（`HOME_EPS`），就对齐到原位、把推动进度清零，直接原地 `floating`，不进 `drifting`，也不发 drifting 事件。离开原位 ≥ 5 cm 时，照旧 2 s 漂回。
  2. `src/levels/s1/puzzles.ts`：加了 `driftBackSaid` 标记，「它漂回去了。」整局只说第一次，符合 text-ch1.md:61。
- 回归：
  - `npm run test:tide` 新增「浮物（BUG-010）：没离开原位就涨潮 → 原地浮起，不进 drifting」。不带修复时这一项会失败，带修复 10/10 通过。原有的「不在锚位涨潮 → 2 s 漂回」不变。
  - smoke 013 的漂回段记录了 `subtitle:show`：断言真的漂回后说了一次「它漂回去了。」；再发一次 drifting→floating 事件后，仍然只有 1 次。`SMOKE_ONLY='013 S1'` 通过。
- 遗留：原位阈值 5 cm 是程序定的。推了不到 5 cm 再涨潮，算「没离开原位」。
