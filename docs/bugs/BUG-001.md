# BUG-001 verify-lod / verify:glb 把场景图外的孤立 -collider 节点算作有碰撞体，puzzleCritical 缺碰撞体照样通过

- 关联：6bb5d37（tools: verify-lod 支持任意 GLB 交付自检）；style-guide §5.4
- 严重度：轻微（只影响工具自检，游戏本身不受影响；要导出器出错 / 手改 GLB 才会出现）
- 测试版本：c73645f 快照 /workspace/qa-tools/snap-c73645f/game

## 复现步骤
1. 用 /workspace/qa-tools/mk-nocollider.mjs，把 art/models/props/prop-lantern-brass.glb 里的 `prop-lantern-brass-collider` 节点从父节点 children 和 scene.nodes 里摘掉。节点本身还留在 JSON 的 nodes 数组里，得到 /workspace/qa-tools/cases/lantern-no-collider.glb。
2. `node scripts/verify-lod.mjs /workspace/qa-tools/cases/lantern-no-collider.glb`，以及 `npm run verify:glb -- <同一文件>`。
3. 对照：用游戏的 AssetLoader（`__game.assets.loadEntries`）加载同一文件，遍历 `gltf.scene`。

## 期望
游戏里拿不到 collider，所以审计应报「✗ puzzleCritical 物体缺 -collider（§5.4 必须）」，退出码 1。真正删掉节点、或改名为 -collision 的用例就是这样报的。

## 实际
- 两条命令都输出「-collider×1」，0 错误，退出码 0。
- 浏览器里加载后，`gltf.scene` 中找不到任何 `-collider` 节点（colliderInScene=[]），而 `parser.json.nodes` 里仍有 `prop-lantern-brass-collider`。也就是说，审计按 JSON 全部节点计数，没有按场景图计数。
- 证据：/workspace/qa-tools/out/part1-browser.log（qa-orphan 一项）。

## 修复说明

- commit：`048c551`（game/ 仓库，信息以 BUG-001 开头）
- 改了什么（`game/scripts/lib/glb-audit.mjs`）：
  - 特殊节点（`-collider` `-interact` `-wall` `-cam` …）一律按场景树判断：从默认场景 `scene.nodes` 往下遍历，和 GLTFLoader 的 `gltf.scene` 一致。只在 JSON `nodes` 数组里、没挂在场景树上的特殊节点报错「在 nodes 列表里但没挂在场景树上」，而且不计数，所以 puzzleCritical 物体会同时报「缺 -collider（§5.4 必须）」，退出码 1。
  - 每个 puzzleCritical 根节点的**子树里**都必须有 `-collider` 和 `-interact`。挂在场景树上、但在子树外的报错；有多个根时逐个检查（白石组的 `-interact` 仍只警告）。
  - 不在场景树上的 puzzleCritical 节点报错，不在场景树上的普通网格只警告（白占包体）。
  - 同一提交里加了一条拦截：任何节点 extras 出现键名 `pivot` 就报错。GLTFLoader 会把这种节点当成枢轴容器，位置可能变成 NaN；美术已改用 `originAt`。另外，加载后任何节点的变换含 NaN 也报错。
  - 顺带：Node 里的 KTX2 贴图改用空纹理占位，带 KTX2 的 GLB 也能完整审计。
- 测试：`npm run test:assets` 新增用例：QA 用 mk-nocollider 改 JSON 的做法、gltf-transform 孤立节点、子树外、多根、非关键物体孤立 collider、`pivot` 字符串和数组、`originAt` 对照。
- 复测：`node scripts/verify-lod.mjs /workspace/qa-tools/cases/lantern-no-collider.glb` 现在输出 2 个错误，退出码 1。art/models 下现有 19 个 GLB 全部仍然通过。
